# U2 next DDL ownership slice: decomp compatibility and canonical schema

Status: **READY_FOR_CONTRACT_REVIEW**, 2026-10-02. Report-only proposal; no implementation, database operation, migration, fingerprint computation, test execution or runtime qualification. This report owns only this file. The adopted STABS source through `34b7287f` is the input; its source review passed, but SQLite and installed acceptance remain unverified.

## Decision and scope

Append one canonical migration `(11, "decomp_schema_ownership")`, preserving migration1–10 identities, their forward operations and the emitted baseline. A required version-binding correction to migration10's direct-repeat branch is specified below. Move persistent corpus `decomp` declarations into `store.py`; remove their execution from `decompile.py`. Keep the independent `decomp_part` file outside the corpus ledger. Adopt **one small compatibility-state table** with the migration, because schema facts currently carry two observable meanings that would otherwise be destroyed by unconditional CREATE/ALTER:

1. Missing `decomp` differs from an installed empty table in the public witness count and fingerprint-stage receipt.
2. Missing `ast_fingerprint` selects `skeleton_hash` for every row. Present `ast_fingerprint` selects that column for every row, including NULL/empty values; the current reader does **not** fall back per row.

The compatibility state records those preexisting schema facts, not an observation of recovered source. A plain `COALESCE(ast_fingerprint,skeleton_hash)`, a nonempty-value fallback, a manufactured `ASTv1:` value, or a table-presence test after migration cannot preserve this contract. There is no unresolved policy question requiring user input: preserve the exact existing semantics and label their limited provenance. No general evidence framework, per-binary measurement ledger, recovery backfill, or matcher algorithm redesign is needed.

This is a single dependency-coherent slice: declaration ownership, migration, state-aware readers/writers, strict admission and frozen deletion support must land together. A DDL-only intermediate patch is not admissible. Wider U2/U22/U82 ownership remains open.

## Canonical declarations and exact metadata meaning

`store.py` owns `DECOMP_TABLE_DDL`, `DECOMP_INDEX_SQL`, `DECOMP_COMPAT_STATE_DDL`, and the bounded pre/post shape definitions. Do **not** interpolate them into `SCHEMA`: migration 1 and all previous ledger prefixes must stay unchanged. `decompile.MAIN_SCHEMA` becomes an alias/composition of the canonical existing decomp table/index declarations for import compatibility, but public corpus operations no longer execute it. No Ghidra, producer, hashlib or decompiler import is needed by migration.

The current 15-column table is canonical: `binary_id INTEGER NOT NULL`, `addr INTEGER NOT NULL`, then nullable INTEGER `ok,n_tokens,n_lines,max_nest,n_calls,n_locals,n_deref,n_index,n_field`, nullable TEXT `ctrl,ops,skeleton_hash,ast_fingerprint`, composite PK `(binary_id,addr)` and `ix_decomp_bin ON decomp(binary_id)`. Keep this declaration, column order, nullability, default absence and lack of FK/CHECK/extra uniqueness. No new orphan cleanup, FK enforcement, reinterpretation of ok, or stricter value validation is part of adoption.

Add this narrowly scoped schema-compatibility declaration (proposed SQL, not executed):

```sql
CREATE TABLE decomp_schema_state (
    singleton INTEGER PRIMARY KEY CHECK (singleton = 1),
    mode TEXT NOT NULL CHECK (mode IN ('absent', 'skeleton_hash', 'ast_fingerprint'))
);
```

Exactly one row `(1, mode)` is required. It is global to the store because the historical column and table-presence decisions were global. It is not binary-owned and is not deleted when removing a binary. There are no default values, timestamps, paths, source text, hashes or generated claims in this table. `mode` records the **logical installed-schema behavior**:

| Observed shape immediately before migration11 | Inserted mode | Behavior after schema-only migration |
|---|---|---|
| No decomp object | `absent` | Physical canonical table is installed empty; logical optional witness remains absent. |
| Supported legacy decomp without AST | `skeleton_hash` | AST column is added NULL for all rows, but matching still selects skeleton globally. |
| Supported decomp with AST, whether empty, all NULL, empty-string or populated | `ast_fingerprint` | Matching still selects AST globally; NULL/empty AST never falls through to skeleton. |

Creating this new metadata row records an observed pre-migration schema fact only. Do not write any existing decomp row or backfill any old fingerprint. Unknown legacy source meaning stays unknown. A missing/corrupt metadata row on claimed v11 is an error, never reconstructed from the physical table, which can no longer distinguish these histories.
