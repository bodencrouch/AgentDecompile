# Task11.6b — owned capture-helper lifecycle packet

## Architecture and bounded change

Keep the existing grid scheduler and the recovery-agnostic native profile primitive. Add one fixed supervisor-owned, single-use **capture process**, running trusted supervisor code. It copies donor bytes; it never executes the donor interpreter, checker or recovery entrypoint. Its process exit ends its file-writing lifetime. No caller-selected executable, Python module, callback, store locator, policy, class or serializer is accepted. The adopted confined target's CHALLENGE/HELLO/READY/START/COMPLETE protocol remains separate and unchanged.

The critical source seam is `src/agentdecompile_grid/worker/native_closure_profile.py:702–782`: `capture_private` currently creates the allocation at :743–748 inside its caller. `OwnedAllocation` and `OwnedCapture` (:412–451) contain process-local FD numbers; sending their JSON or integer FD values cannot transfer capability. A killed child can bypass :768–782 entirely. The next packet must therefore split allocation from copying, keep allocation authority in the parent, and promote that existing live ownership only after authenticated completion **and confirmed helper exit**.

The trusted owner/kernel/supervisor-domain premise in the adopted contract applies unchanged. Exact source/runtime identity establishes which trusted implementation runs, not protection from malicious code admitted by the owner. Host 0700 directories do not isolate unrelated hostile code sharing the UID. No new privileged broker, namespace platform, helper pool, OCI adapter or generalized remote attestation is proposed.

## Fresh allocation bootstrap without hidden scheduler I/O

Choose a **single-use prepared slot**, not a cache of captured roots. During explicit supervisor infrastructure preparation, before active scheduling, the parent creates exactly one fresh empty allocation, retains its private parent and root directory FDs, and starts/authenticates one parked fixed helper. No selected-task, proposal, donor-content or profile-content read, and no copy, occurs during preparation. This uses already provisioned owner profile bytes/pins and anchors; it must not resolve a selected task's profile behind the admission clock. The helper receives the empty root, never its parent directory. This is the narrow prerequisite that avoids hiding synchronous `mkdir/open/exec/proc` work in `poll()`.

Preparation is a cooperative operation: its filesystem and spawn calls can block in the kernel. A 20-second preparation budget and a 30-second prepared-slot idle lifetime are fixed refusal/expiry ceilings, **not** a guarantee of interrupting a stuck parent syscall. Preparation cannot execute on an active scheduler tick, during another owned writer, or as a background thread. If no fully prepared slot exists, capture admission is unavailable; it does not synchronously prepare one. Replenishment occurs only at an explicit quiescent supervisor maintenance boundary. This packet neither installs that driver boundary nor claims continuous scheduler integration. It exposes the requirement for the later lifecycle packet. The tradeoff is deliberate: a small source-only prerequisite instead of a new bootstrap service.

The parent records a boot-local intent and internally generated `capture-<32hex>` name **before** exclusive `mkdir`. Collision refuses; never adopt/delete the existing object. After successful mkdir, open relative to the retained parent with no-follow directory flags, verify root/parent UID, exact initial 0700, device/inode/mount and empty contents using the reviewed primitive checks. Store the actual root identity before spawning or giving any helper access. No capture helper is spawned if root identity is unknown. A failure after mkdir but before root identity creates `AllocationUncertain`, retaining parent/name/creation disposition; it is never capture-ready or automatically removable. This is stronger than passing the existing `OwnedAllocation(-1,...)` partial to a worker.

Directory root identity is `{device:UInt,inode:UInt,mount_id:UInt}` with UInt an exact non-bool integer in `[0,2^64-1]`. Parent also retains parent-directory identity, boot nonce, internally generated allocation ID and a one-use ownership object. These are local ownership records, not document-derived authority. No scanning directories or reopening a name supplied by the helper. A supervisor crash does not create recoverable launch or deletion authority from a journal/JSON; unresolved old allocations stay quarantined for a separately owned recovery procedure.

Prepared means fresh, empty and never previously submitted, failed, cleaned or captured. A rejected/expired/begun slot is permanently consumed; it cannot be reset for another writer. The parent hands out only duplicates of its already authenticated root/donor/document anchors. Parent root and private-parent originals remain noninheritable and retained throughout partial, success, cancellation and quarantine states.

Proposed fixed APIs, with camelCase shown only as descriptive parameter spelling:

- `prepare_capture_slot(ownerInputs, preparationDeadline) -> PreparedCaptureSlot | CapturePreparationFailure`: only quiescent supervisor preparation. Inputs are trusted owner descriptors and immutable runtime/profile bindings, never a request manifest. Failure retains any uncertain allocation/process ownership.
- `begin_capture(slot, seedTiming) -> CaptureRun`: consumes the prepared slot once; pure local bookkeeping and nonblocking IPC only. `seedTiming` is exactly `{admitted_at_ns:UInt,absolute_deadline_ns:UInt}` from the supervisor; it cannot provide paths or replace bindings. Reject expired slot/timing and changed coherent owner-binding identity.
- `CaptureRun.poll(nowNs) -> CapturePhaseUpdate`; `request_cancel(nowNs, reason) -> None`; `take_capture() -> OwnedCapture` once; `take_quarantine() -> CaptureQuarantine` once. No raw FD integer input from IPC.
- Internal `allocate_private_capture(...) -> OwnedAllocation` factors :731–749 for parent use. Internal `capture_into_owned(profile, *, donor_fd, allocation, absolute_deadline)` factors :750–767, requires the supplied root identity and empty single-use allocation, creates no allocation root and accepts no destination pathname.
- Existing `capture_private(...)` remains the composition of these synchronous primitives for compatibility; its existing cooperative/no-hard-walltime warning remains. The process path calls only `capture_into_owned`, never nested `capture_private`.

The child's allocation view omits private-parent access. It contains its inherited root FD and parent-retained expected root identity; exceptions are diagnostic, not a transfer of ownership. Introduce a private copy-result record if needed rather than forging an `OwnedAllocation` with a pretend parent FD. All ordinary file writers still close before :756 verification and :760 freeze; :761 independently authenticates the final complete frozen destination. No copy safeguard may be bypassed by the split.

## Clean helper identity and descriptor contract

`HelperRuntimeBinding` is trusted supervisor configuration, outside the runtime profile's existing v1 public schema. Its exact data-only fields are `{schema:"agentdecompile.native-capture-helper-runtime.v1",runtime_inventory_sha256:Hash,interpreter_sha256:Hash,entry_sha256:Hash,capture_module_sha256:Hash,profile_module_sha256:Hash,environment_sha256:Hash}`. Hash is 64 lowercase hex. `runtime_inventory_sha256` binds the owner-maintained immutable supervisor helper installation (interpreter, bootstrap, fixed imports and native dependencies). The parent authenticates this installation during preparation and retains its identity. File hashes beside a mutable installation, helper-reported hashes, `sys.executable`, PATH discovery and version text alone are insufficient. Missing immutable trusted installation refuses `runtime_dependency_unavailable`. This is a supervisor trust prerequisite, not a new donor-runtime closure receipt or an automatic installation task.

Launch a fixed owner-resolved interpreter with `-I -S -B` and a fixed entry script from that installation. No `-m` search through the host workspace, `PYTHONPATH`, inherited venv/site, `.pth`, `.pyc/.pyo`, cwd import, source code from IPC or arbitrary `import_modules`. The entry establishes its immutable allowlisted stdlib/lib-dynload and package source paths before imports. Bind actual source bytes of entry/controller/profile modules and required package initializers; `agentdecompile_grid/__init__.py` imports `core`, so the closure cannot be declared to consist of only two filenames. Parent and helper bindings must agree before BEGIN. No execution of donor files or dependency discovery with `ldd`.

Construct environment from scratch, exactly `{LANG:"C",LC_ALL:"C",TZ:"UTC"}`; fixed safe cwd in the trusted installation, stdin `/dev/null`. No HOME/TMP/PATH lookup is needed for this copier. Do not use `SubprocessSandbox.child_env` (`sandbox.py:238–248`) or `run_manifest` (:381–390). Fixed helper writes no files except beneath its inherited capture root and performs no subprocess/thread creation, signal delegation, store access or network operation. This is a trusted single-process implementation property requiring source review and later actual process qualification; pidfd does not contain malicious descendants. Unexpected fork/exec/delegation makes this profile unavailable, never “covered by process-group kill.”

Exact inherited descriptor allowlist after exec:

| FD | Access and owner |
|---|---|
| 0 | Trusted `/dev/null`, read-only. |
| 1, 2 | Separate bounded diagnostic pipes; parent retains read ends. |
| 3 | Private anonymous `AF_UNIX/SOCK_SEQPACKET` control endpoint. |
| 4 | Donor directory anchor, read-only/no-follow; no path chosen by task. |
| 5 | Fresh destination directory anchor, read-only directory FD; permits descriptor-relative creation by trusted code, not immutable authority. |
| 6 | Immutable profile byte document, read-only, ≤64 KiB. |
| 7 | Immutable inventory byte document, read-only, ≤8 MiB. |

Document descriptors are sealed anonymous **data** files prepared from already provisioned owner bytes by the supervisor with write/grow/shrink/seal seals and reopened read-only, never executable code. Parent retains the canonical bytes and independent owner pins. Helper validates seals/access/size, reads them boundedly only after BEGIN, and invokes `load_profile` with retained owner pins. Inherited FDs are explicitly duplicated to collision-safe fixed numbers with all others closed; process launch must not transiently inherit signer/logwriter/CAS/foreign descriptors. Helper marks 3–7 close-on-exec and never execs again. Parent private-parent FD, signing keys, log writer, sockets, foreign pidfds and donor runtime executable FDs are absent. FD cleanup on failed spawn preserves parent originals.

Use a direct unreaped child handle. Before accepting any helper frame or permitting mutation, parent obtains and retains its mandatory pidfd, actual outer PID, `/proc` start ticks, expected UID/GID, parent relationship, executable/argv and helper-runtime binding. Do not reap before pidfd acquisition; a dead unreaped direct child cannot silently become a reused PID. Bound identity reads to 64 KiB each/512 KiB aggregate during preparation. No numeric PID signal fallback, no pre-fork `SO_PEERCRED` substitute. Any inability to bind the owned process refuses `owned_process_identity_unavailable`. If identity acquisition fails, close the channel before BEGIN; fixed helper's bounded bootstrap/EOF path exits without copying, while uncertain ownership stays quarantined. Parent disappearance uses fixed Linux parent-death SIGKILL with getppid race checks before/after installation; it does not promise immediate D-state termination or restart cleanup.

## Exact private capture protocol

This is `agentdecompile.native-capture-ipc.v1`, distinct from `agentdecompile.native-region-ipc.v1`. Anonymous nonblocking seqpacket socketpair; `SO_PASSCRED` enabled on both receivers before spawn. Each received datagram requires exactly one kernel `SCM_CREDENTIALS` tuple matching the retained peer PID/UID/GID and live process association. The child validates the parent identity established during bootstrap. No ancillary descriptors in any frame; close all received SCM_RIGHTS before rejecting, including truncated ancillary input. Missing/extra credentials, `MSG_TRUNC`/`MSG_CTRUNC`, changed sender, nonce, sequence or unexpected frame are terminal failures. No pipe fallback.

Canonical strict JSON uses the Task11.6a canonical convention and exact keys. Each frame is exactly `{schema,kind,nonce,seq,payload}`. Nonce is fresh parent-held 64-hex; seq exact non-bool integer beginning at zero independently in each direction. Fixed payload strings ≤256 UTF-8 bytes, no NUL; depth ≤4, ≤64 object members; envelope ≤4 KiB except the smaller limits below. No floats, duplicate/unknown/missing fields, arbitrary refs or fragmentation.

| Direction/state | Kind/sequence | Exact payload and cap |
|---|---|---|
| Parent, preparation | `CHALLENGE`, 0 | `{profile_id,profile_sha256,inventory_sha256,helper_runtime_sha256,allocation_id,root_identity}`; ≤2 KiB. `profile_id` is the fixed adopted profile; `allocation_id` is 32-hex; helper runtime hash is canonical binding digest. All authority comes from parent state. |
| Child, after bootstrap checks | `HELLO`, 0 | `{helper_runtime_sha256}`; ≤1 KiB, echoes challenge nonce, reports no capability independently. |
| Child, parked | `READY`, 1 | `{allocation_id,root_identity,profile_sha256,inventory_sha256}`; ≤2 KiB. Checks inherited anchors/document metadata/limits, but performs no donor reads or capture mutation. |
| Parent, admitted capture | `BEGIN`, 1 | `{capture_deadline_ns:UInt,absolute_deadline_ns:UInt}`; ≤1 KiB. Child compares to same-host monotonic clock, validates remaining positive time and ≤90 s, never extends. |
| Child, successful primitive return | `COMPLETE`, 2 | `{allocation_id,root_identity,profile_sha256,inventory_sha256,entry_count:UInt,total_file_bytes:UInt}`; ≤2 KiB. Count/bytes must equal pinned inventory totals and adopted caps. No path, FD number, ref or inventory blob. |
| Child, terminal refusal | `ERROR`, next child seq | `{reason:Reason,detail:String}`; ≤2 KiB; detail ≤256 bytes. At most one terminal ERROR, instead of the next expected child message, including during bootstrap. |

Parent sends only CHALLENGE and BEGIN. Cancellation is a parent-owned pidfd signal operation, not an optional request waiting for a blocked copy loop to read a socket. Child closes data/root/control/log descriptors and exits zero after COMPLETE; exits nonzero after ERROR. The parent accepts COMPLETE provisionally until exit, EOF and bounded diagnostic drain. Missing COMPLETE with exit zero, ERROR with exit zero, COMPLETE with nonzero exit, duplicates, post-terminal frames, truncated last frame, EOF early or unknown delivery state are failures. A failed parent send is not BEGIN authorization; if send outcome is uncertain, consume slot and cancel/quarantine.

Allowed `Reason` values: `profile_pin_mismatch`, `supervisor_domain_unavailable`, `capture_integrity_failed`, `root_layout_unsupported`, `owned_process_identity_unavailable`, `runtime_dependency_unavailable`, `limit_exceeded`, `deadline_exceeded`, `ipc_binding_invalid`, `cleanup_incomplete`. Unexpected internal exception maps to `capture_integrity_failed` with bounded detail, never an exception pickle or traceback dump. Preparation may additionally report adopted `profile_not_configured`. Cancellation by caller uses local `cancelled` disposition; it does not invent a producer refutation.

The parent receives no ownership via this socket. Partial handoff means the live parent slot moves to `CaptureQuarantine`; successful handoff means the exact retained parent root/private-parent descriptors move once into parent `OwnedCapture`, with `CaptureIdentity` made from the parent's pins/identity and authenticated fixed-helper completion. Child `OwnedCapture` objects are never deserialized. SCM_RIGHTS root transfer is unnecessary because the parent already has the root. Success depends on the actual reviewed helper doing full copy/rehash/freeze and the trusted domain preventing other writers; matching child JSON alone cannot attest any of that.

## State, bounds and ownership

Preparation states: `allocating -> helper_bootstrap -> prepared`; failures become `allocation_uncertain`, `terminating` or `quarantined`. No helper can mutate in these states. Capture states: `prepared -> awaiting_begin_delivery -> copying -> completion_pending_exit -> capture_ready`; every state has a failure edge to `terminating -> killing -> quarantined_pending_io|quarantined`. `capture_ready` is not launch-ready, `ready_for_collect`, signed evidence or current admission.

For an admitted seed, `absolute_deadline=admitted_at+600s` is captured before any proposal/capture read. Capture deadline is `min(capture_entry+90s, absolute_deadline-510s)`, preserving stage100, launch20, run300, tree20, export40, collection10 and seal20. BEGIN, copying, both full destination checks, freeze, report delivery, diagnostics and confirmed exit must all fit that capture deadline. Already spent pre-admission preparation is explicit infrastructure preparation, not credited as a completed job phase or fresh capture. No donor/profile document reads occur before BEGIN. A slot expiring before admission is cancelled/quarantined and never grants extra time.

`poll` processes at most 16 IPC/status/diagnostic events and 64 KiB combined bytes per call, stops by 5 ms cooperative CPU/monotonic budget, and uses only nonblocking socket/pipe/pidfd readiness and nonblocking owned-child reap. It never opens/stats/reads a capture path, loads a profile document, hashes a tree, launches a process, waits/sleeps, or removes a directory. Framing and JSON caps apply before allocation/parse. The 5 ms contract bounds work scheduled by the implementation, not kernel scheduling latency. No unbounded draining of a busy peer. Diagnostics are capped at 1 MiB per stream/2 MiB aggregate per capture, counted even when discarded; overflow fails/cancels. Total control traffic ≤16 KiB per direction, at most two parent frames and three child frames on a successful run; no heartbeats. Capture uses zero CAS refs and no output-ref traversal.

Fixed helper soft **and hard** limits before READY: CORE=0, NOFILE=128, FSIZE=256 MiB, AS=2 GiB, CPU=90 s, NPROC=32 under the dedicated trusted supervisor UID. The reviewed traversal holds depth-bounded anchors, so arbitrarily shrinking NOFILE below the adopted 128 would need new evidence. NPROC is an independent UID-scoped ceiling, not single-process containment; fixed helper code must not fork. Copy caps remain 16,384 entries, 8 MiB inventory, 512-byte paths/depth24, 256 MiB/file, 1 GiB bytes, 64-KiB chunks. Do not call `apply_limits` (`sandbox.py:348–373`), which treats zero as unset and retains old hard limits. Missing required limit support or impossible installation refuses. Limits do not certify host capacity or prevent blocked filesystem I/O.

`request_cancel` is idempotent, invalidates any provisional success immediately, sends SIGTERM through the retained pidfd and reserves at most five seconds before SIGKILL through the same pidfd. Confirm exit within at most another five seconds; truncate grace to the phase/outer time remaining. Normal COMPLETE also must obtain confirmed exit by the capture deadline; report-before-exit never suffices. At expiry, send SIGKILL if not already sent and return a finite `quarantined_pending_io` result if exit is still unconfirmed. No wait past the deadline to manufacture success. Later passive observation may see exit, but cannot resurrect the timed-out capture.

Confirmed exit requires owned pidfd exit readiness plus matching nonblocking direct-child reap status. Retain both identity and pidfd until that fact is consumed; an unobserved exit, signal return, EOF, timer expiry or a PID lookup miss is insufficient. No descendant writer is permitted; the fixed no-fork helper and absence of writable FD transfer are the supported premise. D-state/ambiguous I/O produces `kill-failed`, keeps all allocation anchors, blocks deletion/reuse/new writer on this capture lane, and permits unrelated independent lanes. Kernel I/O can finish before SIGKILL takes effect; do not claim instant cancellation, immutability or cleanup while that remains possible.

## Cleanup and future RunningJob adapter

Local `CapturePhaseUpdate` is exactly one immutable variant: `{state:"running"|"terminating"|"killing"}`, `{state:"capture_ready"}`, `{state:"quarantined",reason:ReasonOrCancelled}`, or `{state:"quarantined_pending_io",reason:ReasonOrCancelled,kill_action:"kill-failed"}`. The live ownership handle stays on `CaptureRun`; updates carry neither transferable authority nor file descriptors.

`CaptureQuarantine` retains slot/allocation ownership, pidfd/start identity, cancellation timestamps and completion/refusal disposition. `request_cleanup(quarantine) -> CleanupDisposition` is idempotent and metadata-only: `blocked_pending_exit`, `queued_owned_removal`, `cleanup_incomplete` or `removed`. Only confirmed-exit records can enter queued removal. `removed` is possible only after a separately executed, confirmed-exited bounded removal operation succeeds, never by closing FDs. `OwnedAllocation.close()` (:422–428) remains handle release, not cleanup.

The **removal interface**, required before later lifecycle integration claims actual cleanup, consumes the same retained parent/root capability, checks descriptor-relative root name against that exact device/inode/mount before every root-level mutation, and removes only descendants of that fresh allocation with no-follow walks, mount checks, depth/count/path caps and a 20-second cooperative cleanup budget. Never follow symlink targets or traverse a replaced/foreign name. Root permissions may be restored for removal only through its retained FD, after confirmed writer exit. A mismatch, missing ownership anchor, unknown mkdir outcome or supervisor restart remains quarantine; no search by digest/name and no ordinary `rmtree` on a reconstructed path. Enumeration rejects unexpected mount/special-object anomalies and retains uncertainty rather than deleting broadly.

Blocking removal cannot run inside `poll` or `RunningJob.cleanup()`. It requires a separately owned fixed removal helper, started only after the capture helper is confirmed gone, with root/parent authority and the same pidfd/finite-cancellation rules, or remains queued quarantine. Its source implementation/qualification is a mandatory followup; this packet authors only the exact queue/ownership interface and cannot claim physical cleanup. Removal helper D-state retains ownership and blocks the next writer too. No cancellation grace or cleanup retry extends the admitted 600-second job deadline; unfinished cleanup becomes explicitly retained maintenance debt. Descriptors are released only after verified removal or explicit ownership transfer to the supervisor quarantine registry, never dropped with the orphan handle.

`worker/loop.py:343–356` immediately collects/cleans when a job returns `exited`; :520–525 drops orphans on `exited` and calls cleanup. Consequently a later `NativeClosureRunningJob` must translate `capture_ready` to its **stage** phase, never public `exited`. Only complete target-tree termination plus export can yield successful `exited`. A failure yields no positive result/signature; its ownership moves to the supervisor registry before loop cleanup. `kill-failed` must preserve the per-supervisor capture admission latch even after slot removal; existing `orphans` alone does not prevent a next writer. The later adapter must transfer confirmed-dead but not-yet-cleaned orphan ownership before allowing `_poll_orphans` to discard the job. No shared loop behavior is changed by this packet.

## Compliance, risks and mandatory followups

Dependency direction stays profile primitive <- capture supervisor/helper <- future native sandbox; no recovery imports enter grid worker primitives and no reverse import from profile into lifecycle creates a cycle. Public profile/inventory schemas and legacy RunningJob/JobOutcome contracts remain unchanged. The descriptor ownership split preserves separation of concerns: primitive authenticates bytes; parent authenticates the process and owns lifetime; later collector/seal/reader authenticate execution and current admission.

Main residual risks are real deployment premises and kernel stalls, not solved by metadata: trusted helper installation/domain integrity; synchronous quiescent preparation; helper no-fork/no-FD-delegation correctness; later cleanup implementation; and scheduler integration preserving quarantine ownership. Missing capabilities refuse without weaker fallback. The prepared-slot prerequisite and deferred removal are explicit costs of this bounded packet, not claims that all adopted lifecycle obligations are finished.

Mandatory later packets remain: physical removal helper; full NativeClosureRunningJob/loop admission before proposal reads; bounded stage and export helpers; ELF/loader/RPATH/executable-stack/transitive Python qualification; pinned launcher/filter and namespace/noexec/seccomp enforcement; target startup barrier with its original protocol; fixed P2 role-plan/entrypoint; authenticated collection; exact guarded local seal/retry/unsigned-restart quarantine; separately versioned current-P2 reader. Capture-ready is never launch-ready. P3.1, producer qualification, source/corpus joins, whole-image C+floor/max-C and game runtime acceptance remain unchanged and open.
