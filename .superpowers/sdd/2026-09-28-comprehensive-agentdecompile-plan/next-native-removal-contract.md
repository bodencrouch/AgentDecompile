## Decision, source seams and exact ownership

Add one fixed, single-operation removal helper and a small supervisor phase object. The parent keeps original allocation authority throughout. The helper receives duplicates of exactly that allocation's retained directory anchors and may mutate only that allocation. It cannot select a target, adopt a path, accept callbacks or reconstruct ownership. Parent/root access is a deliberate addition relative to the capture helper, which receives no private-parent descriptor. It requires the same trusted supervisor UID/domain; private mode 0700 alone does not constrain another hostile unconfined process sharing that UID.

## Sole deletion authority and exclusion of other users

`request_cleanup(quarantine)` remains idempotent, metadata-only and nonblocking. Its public disposition vocabulary remains `blocked_pending_exit | queued_owned_removal | cleanup_incomplete | removed`. It neither spawns nor traverses nor chmods/unlinks. A queued object is eligible for separate preparation, not evidence of physical deletion.

Only an exact live `CaptureQuarantine` still occupying its original `CaptureLane` can be claimed once per admitted ownership generation. A generation can advance only through the qualified maintenance transfer defined below; it is never reset after a timeout. The parent must retain all of:

1. Its original `OwnedAllocation` (not `AllocationUncertain`), live noninheritable root/parent descriptors, exact recorded `(device,inode,mount_id)` for both, internal `capture-<32 lowercase hex>` name and nonempty allocation boot nonce; none reconstructed from records, names or FD integers received over IPC.
2. Its local creation/spawn history. If a capture writer was ever attempted, the same retained `OwnedProcess` must have valid identity, no `identity_lost`, and confirmed matching pidfd/direct-child reap. `process=None` is permitted only on the recorded branch where spawn was never attempted, not as replacement for a lost process. Unknown spawn, absent pidfd identity, arbitrary `confirmed_exit=True` data, externally reaped child or PID disappearance cannot supply authority.
3. Exclusive local mutation ownership, no previously transferred capture/target user, no concurrent remover and no outstanding writer. The current packet accepts capture-failure/expired-slot quarantines only. It does not accept a bare successful `OwnedCapture`, the synchronous primitive's partial directly, a mounted execution root, or a later job-work directory. Future successful-capture retirement must provide its own complete reader/tree/mount release proof before reusing this seam.

Add private boot-local claim state to the quarantine: unclaimed, claimed by exact removal object, failed-and-retained, or terminal qualified removal. Retain a non-bool UInt64 `removal_generation`, initially zero, and the exact private `RemovalClaim` object for that generation; overflow refuses. The generation number alone is not authority. The original quarantine remains the lane occupant and owns original descriptors while a helper receives duplicates; claiming never clears the lane. Every preparation/run/cancel/finalization operation must match both the exact current claim object and its captured generation before it may send IPC, signal, release an FD, alter state or release the lane. A failed claim is not reset to unclaimed by polling, exit observation, timeout or queue admission. Store allocation/process identity, previous refusal and timing in that same object. Retain the capture-writer process record separately from the new remover record; never overwrite writer provenance with the removal PID. Record no-writer versus attempted-spawn provenance at the existing acquisition branches, before a claim can be issued. Duplicate begin, another object with matching fields, stale run, consumed token or caller-supplied record cannot claim it. This is trusted Python object provenance, not a claim of security against malicious code inside the supervisor.

An `AllocationUncertain`, unknown mkdir outcome, replaced/missing root name, closed anchor, supervisor restart or lost object provenance remains `cleanup_incomplete`. No root search, pathname reopen, digest directory adoption, journal replay, ordinary `shutil.rmtree`, shell `rm`, or FD-number serialization establishes permission. An old JSON journal may explain retained debt but is never a deletion capability.

## APIs, quiescent preparation and deadlines

Proposed fixed internal APIs:

- `prepare_removal(quarantine, ownerInputs, timing) -> PreparedRemoval | RemovalPreparationFailure`: explicit quiescent single-threaded supervisor maintenance only. Validate local claim/history, authenticate the immutable helper installation, retain duplicate anchors, start/authenticate one fixed parked direct child. No tree mutation occurs. Capture writer exit is required before even spawning this helper.
- `begin_removal(prepared) -> RemovalRun`: consumes one prepared object, checks its exact quarantine/lane claim and retained timing, sends one nonblocking BEGIN. No filesystem reads, hashing, process spawning or waits.
- `RemovalRun.poll(nowNs) -> RemovalPhaseUpdate` and idempotent `request_cancel(nowNs, reason)`: bounded metadata operations only. `take_disposition()` is one-use metadata finalization; only a qualified successful run can publish `removed` and release anchors/lane. Failed runs retain their quarantine and remover process record.
- Internal `remove_owned_tree(view, *, deadlineNs) -> RemovalSummary`: synchronous helper-only primitive, no directory allocation and no pathname root. `view` contains inherited root/parent descriptors and independently parent-held identities/name bound before BEGIN. It cannot be constructed from a task/receipt. Tests may specify this function directly; production calls it only from the fixed entry after BEGIN.

`ownerInputs` is owner configuration only: retained immutable installation descriptor/path, removal runtime binding and canonical inventory bytes, dedicated-domain/quiescence declarations. It supplies no donor, profile documents, CAS, signer, task or target directory. Existing owner pins are provisioned prerequisites, not this packet's installation work. `timing` is a supervisor-created exact local record `{mode:"job"|"maintenance",attempt_id,deadline_ceiling_ns,original_job_deadline_ns}`: attempt ID is fresh 32-hex, deadlines are UInt, and original deadline is null only for an allocation never admitted to a job. Job mode requires equality of ceiling and the retained original job deadline. Maintenance mode requires the exact acknowledged live transfer and a ceiling at most 20 seconds after its maintenance preparation entry; preparation consumes that maintenance budget too. These values cannot come from a task or IPC response.

The attempt starts before any removal preparation or installation read: `attempt_deadline=min(preparation_entry+20s, deadline_ceiling)`. This single 20-second budget covers installation authentication, helper bootstrap/READY, parking, BEGIN, physical removal, reporting, diagnostics and confirmed exit. Preparation uses that same deadline and no active scheduler tick/background thread. It can block in a kernel syscall; its ceiling is cooperative, not guaranteed parent interruptibility. Revalidate elapsed time after each operation. Record unknown spawn before entering the syscall and retain any returned child immediately; failures preserve parent originals. Before BEGIN, close the control channel on failed/uncertain preparation and retain the process record; fixed-helper EOF/expiry exits without mutation. Bind the child bootstrap deadline to the same attempt during CHALLENGE; parent cancellation never gains a new preparation grace period. A parked prepared remover expires at that same attempt deadline; no additional idle allowance exists; an expired/failed/begun object is permanently consumed. No preparation after the job ceiling is disguised as part of that job.

For job-associated cleanup, `deadline_ceiling` is the original admitted 600 s absolute deadline, with no reset or borrowed phase reservation. Removal deadline is the unchanged `attempt_deadline` retained from preparation, never `begin_time+20s`. BEGIN cannot refresh it. The earlier installation/bootstrap costs plus BEGIN, metadata preflight, permission restoration, all deletions, postconditions, COMPLETE delivery, diagnostics and confirmed exit must fit it. Cancellation/grace fits inside the same deadline. Removal is not a new 20s appended to 600 s and cannot postpone an expired seal or revive a failed job.

If insufficient time, capability or quiescence remains, retain explicit maintenance debt. A later separately owned quiescent maintenance attempt may receive a fresh bounded maintenance ceiling only after an explicit live ownership transfer has completed and all prior helpers have confirmed exit. It records `maintenance`, original expired job identity/deadline and a fresh attempt identity; it is not an extension or successful completion of that job. This packet supplies the transfer interface and first attempt, not a background retry driver. Retry is never automatic, never overlaps an uncertain writer and never recreates authority from disk. A partial retry must re-preflight the exact still-owned remainder and preserve the earlier uncertainty record.

## Exact private removal protocol

Use distinct `agentdecompile.native-removal-ipc.v1`, not the capture or target protocol. Canonical strict JSON uses Task11.6a conventions, exact envelope `{schema,kind,nonce,seq,payload}`, 64-hex fresh parent nonce and independent non-bool UInt sequences. UInt is 0 through 2^64−1. Root/parent identity each has exactly `{device:UInt,inode:UInt,mount_id:UInt}`. Allocation ID is 32 lowercase hex; the helper derives only `capture-` plus that already parent-owned identifier. It accepts no path string.

| Direction | Kind/sequence | Exact payload; envelope cap |
|---|---|---|
| Parent | CHALLENGE 0 | `{allocation_id,root_identity,parent_identity,helper_runtime_sha256,attempt_deadline_ns}`;2KiB. |
| Child | HELLO 0 | `{helper_runtime_sha256}`;1KiB. |
| Child | READY 1 | `{allocation_id,root_identity,parent_identity}`;2KiB. Child checks inherited anchors and root-name association without mutation. |
| Parent | BEGIN 1 | `{removal_deadline_ns,deadline_ceiling_ns}`;1KiB. Child requires positive remaining time, at most 20 s, equality with the CHALLENGE attempt deadline, and no extension beyond ceiling. |
| Child | COMPLETE 2 | `{allocation_id,root_identity,parent_identity,removed_entries:UInt,root_unlinked:true}`;2KiB. `removed_entries` excludes root and is at most 16,384. |
| Child | ERROR next sequence | `{reason,detail}`;2KiB, detail at most 256 UTF-8 bytes, NUL-free. At most one terminal message. |

CHALLENGE and BEGIN are the only parent frames; no heartbeat, path, FD numbers, profile document, inventory blob, continuation cursor or output refs. Entire envelope at most4KiB, depth 4, 64 members; caps precede decoding/allocation. Reject floats, duplicate/extra/missing fields, surrogate strings, noncanonical bytes and bool-as-integer. Aggregate traffic 16 KiB/direction. Every nonempty frame requires exactly one matching kernel SCM_CREDENTIALS tuple and live retained process association. Reject truncation, extra ancillary data and all rights; close every delivered SCM_RIGHTS descriptor before refusal, including truncated ancillary cases. No fallback transport.

Allowed wire `reason` values are exactly `profile_pin_mismatch`, `supervisor_domain_unavailable`, `root_layout_unsupported`, `owned_process_identity_unavailable`, `runtime_dependency_unavailable`, `limit_exceeded`, `deadline_exceeded`, `ipc_binding_invalid`, `cleanup_incomplete`. Unexpected exceptions map to `cleanup_incomplete`; local cancellation adds `cancelled` only in supervisor disposition, never as evidence about a producer. Map reused profile/helper exceptions to this fixed set without extending the public runtime profile schema.

Parent validates identities/count cap against its own authority; child echo alone grants nothing. COMPLETE is provisional until authenticated exactly once, zero matching child exit, control/stdout/stderr EOF and bounded drain all before deadline. ERROR/nonzero exit, zero exit without COMPLETE, COMPLETE followed by extra data, uncertain BEGIN/send, late delivery, EOF early or cancellation invalidates success. Child sends COMPLETE only after actual primitive success/postchecks, closes its descriptors and exits immediately; exception gives a bounded constant diagnostic, not arbitrary paths/tracebacks. Cancellation uses parent pidfd signals, not a request blocked behind filesystem I/O.

## Descriptor-relative removal algorithm and anomaly policy

No root-path reconstruction, realpath, chdir into the target, glob, pathname recursion, `rmtree`, recursive chmod or inventory-selected deletion. The helper operates only on retained FDs and single checked child components. Trusted procfs FD aliases may inspect already retained kernel descriptors; they must not reopen an arbitrary root name as replacement authority.

1. **Authenticate anchors before mutation.** Check retained parent/root type, supervisor UID, original device/inode/mount triples and nonnegative valid ownership fields. Parent mode must remain 0700. Root must still be a directory on that parent mount/device with supported 0555 frozen or 0700 partial mode; unknown/set-ID/sticky modes refuse. Open the internal name relative to retained parent with `O_PATH|O_NOFOLLOW|O_CLOEXEC` (and directory validation), obtain its own mount ID, and compare it to the retained root. A symlink, missing name, foreign replacement or same-device bind mount refuses. Close temporary name anchor; never substitute it for the original root.
2. **Bounded read-only metadata preflight.** Enumerate through descriptor-relative retained directory FDs, no following links. Cap 16,384 descendants, UTF-8 relative paths 512 bytes/depth 24, and 8 MiB retained metadata; cap counters before append/allocation. No unbounded listdir, sorting of an uncapped list or retries on changing directories. Validate components with the existing normalized path rules. Use O_PATH/no-follow inode anchors first; validate type/mount before opening a directory for enumeration, so a replacement FIFO/device is never opened for content I/O. Reject non-directory/non-regular/non-symlink objects, unexpected mounts including same-device binds, differing owner, hardlinked regular files/symlinks, set-ID/sticky/security-capability anomalies, invalid names and identity changes. Reuse bounded no-follow security-xattr semantics where applicable; missing support refuses. Do not read or resolve symlink targets: unlinking the link never authorizes target traversal, even for dangling/outward links. Do not hash or read regular-file content.
3. **Retain an exact bounded deletion plan, not durable authority.** Store relative components and observed device/inode/mount/type/mode/link/owner/ctime metadata for this one helper attempt. Preflight itself performs no mutation and brackets enumeration against spontaneous change. Partial captures need not match the full pinned inventory, so deletion does not require unavailable capture success. The plan contains only observed descendants of the authenticated allocation. A second removal walk must match the plan; extra/missing/replaced objects refuse rather than expanding its scope. Two complete metadata passes are bounded to at most 32,768 descendant visits, plus depth-bounded identity guards and one final empty check per directory. Temporary descriptor usage is depth-bounded and must fit NOFILE 128; close per-entry anchors deterministically.
4. **Guard every mutation.** Immediately before every root-level mutation, including root fchmod, unlink/rmdir of an immediate child and final root rmdir, recheck both retained anchors and parent-name-to-root device/inode/mount association as in step1. Apply that same guard before each descendant mutation too, then validate the retained ancestor chain and the exact named entry against the plan. Directory traversal holds retained ancestor FDs; never follow a replacement name into another tree. For an entry's unlink/rmdir, no-follow pin/stat immediately before the syscall must match the retained expected inode/type/mount. Mount ID is mandatory, not st_dev alone. Checks are fail-closed, with no retry on mismatch.
5. **Restore only directory permissions required for removal.** After confirmed writer exit and BEGIN, restore root/descendant directory permissions to 0700 only by `fchmod` on that exact retained checked directory FD. Never pathname chmod, symlink chmod, file chmod, chown, remount or special-attribute repair. Partial 0700 directories need no change; frozen 0555 directories become writable only for their now-exclusive remover. Ordinary files may be partial 0600/frozen 0444 or 0555; unlink needs no restored file permissions. After its own chmod/removal, refresh expected directory metadata to account for those exact successful local mutations; do not compare an unchanged preflight ctime/nlink against a directory the remover itself changed. Unexpected changes still refuse.
6. **Delete leaves then empty directories.** Regular files and symlinks are unlinked relative to their retained parent; directories use descriptor-relative rmdir only after the planned children are gone and a bounded empty check succeeds. Never follow symlinks, cross mounts or remove the private parent/siblings. Root's original internal name is rmdir'd from original private parent only after a final root guard and empty check. Record that this exact syscall succeeded; ENOENT is not idempotent success on an initial/remnant attempt.
7. **Verify postconditions before COMPLETE.** After successful final rmdir, no-follow lookup of that exact name under the retained parent must return ENOENT; retained root must still have its original device/inode/mount and show detached-directory link state (`st_nlink==0`) on the supported Linux filesystem. Parent identity remains unchanged. Any unexpected reappearance, unsupported detached-root semantics, error or deadline overrun yields cleanup uncertainty, even if removal probably happened. Do not rerun the pre-removal name-present guard after successful rmdir. Send COMPLETE only after these explicit postconditions; retain original parent-side FDs until matching helper exit and qualified finalization.

Every open/stat/xattr/enumeration/chmod/unlink/rmdir and bounded metadata step checks the cooperative deadline before and after. These calls can block. No algorithm here promises an atomic directory transaction or prevention of hostile same-UID mount/rename races: the adopted trusted domain and exclusive writer premise are necessary. Rechecks detect inconsistency but are not a kernel compare-and-unlink operation. A violated premise, anomaly or partial failure stops work and retains the remainder; no rollback tries to recreate deleted files or refreeze an uncertain live writer.

## Poll, cancellation, success and retained debt

`RemovalRun` transitions `prepared -> awaiting_begin_delivery -> removing -> completion_pending_exit -> removed`; failures go `terminating -> killing -> quarantined_pending_io | quarantined`. Preparation failures can retain `process_unknown` or `cleanup_incomplete`. A removal phase update contains only `{state}` for active states or `{state,reason,kill_action?}` for failure; successful summary contains no transferable capability. It is not a `RunningJob` and returns no public scheduler `exited` state.

One poll schedules at most 16 events and 64 KiB combined control/log bytes, stopping by 5 ms cooperative monotonic work budget. Use nonblocking socket/pipe reads, pidfd readiness and matching nonblocking owned-child reap only. Reserve full receive-frame cost even on malformed input; count discarded diagnostics. No tree/installation/proc-path read, hash, stat, spawn, chmod, deletion, sleep or blocking wait in poll, begin, request_cleanup or future RunningJob.cleanup. Logs cap 1 MiB per stream / 2 MiB aggregate; overflow cancels. Missing process identity fails even when no IPC is ready. Deadline and identity checks bracket event processing.

Cancellation is idempotent and immediately invalidates provisional COMPLETE. TERM through retained pidfd, at most 5 s to KILL through that same pidfd, at most another 5 s to confirmed exit; truncate both to removal/deadline ceiling. At expiry send KILL if not already sent and return finite `quarantined_pending_io`/`kill-failed` if exit is unconfirmed. Never numeric-PID fallback, waiting beyond deadline, retrying mutation from poll, or promoting after a late report/exit. Kernel I/O may finish before KILL takes effect; do not claim instant cancellation or that a D-state remover stopped touching the root.

A COMPLETE/zero-exit/EOF tuple qualified before deadline permits a local terminal removal tombstone, descriptor release and lane release once. `request_cleanup` may report `removed` idempotently from that internally minted terminal tombstone after lane release; an arbitrary mutable state string or closed descriptors do not qualify it. Validate the exact claim before clearing `lane.occupant`; never clear another occupant. The report remains physical directory removal only, not secure erasure or proof of execution correctness.

For every other outcome keep original root/parent handles, claim history, helper runtime/process/pidfd identity, timestamps, reason and partial-removal state in the same quarantine or explicitly transfer them to a boot-local supervisor registry. The bounded packet must implement the following generation transition seam; the later packet supplies its maintenance driver, not new authority rules. Transfer must atomically move the exact object/descriptor ownership and admission latch to an acknowledged registry entry before the sender relinquishes it; serialization/acknowledging a filename is insufficient. The registry is an in-memory owner for unresolved resources, not a path-discovery service. Preserve at most the existing outstanding capture-lane allocation; refuse new admission instead of accumulating an unbounded quarantine queue.

**Qualified transfer and one-use maintenance rearm.** An internal `transfer_removal_debt(quarantine, expectedClaim, recipient) -> MaintenancePermit` is a quiescent metadata-only ownership transaction. `recipient` is an already provisioned boot-local supervisor debt holder with capacity for this exact lane, not a callback or deserialized path. Implement its minimal one-entry ownership holder and transfer seam in `native_removal.py`; no background scheduler or durable replay is included. It must perform these steps as one indivisible local transition. There are exactly two entry forms: retirement of the exact failed current claim A, or **initial maintenance transfer** with `expectedClaim=None`. The latter is allowed only for original unclaimed generation zero, an internally recorded absence of any prior removal preparation/spawn/claim/transfer, and the still-live capture-failure/expired-slot quarantine after its capture writer is qualified gone (or was never attempted). This covers an expired capture slot never admitted to a job, retaining `original_job_deadline_ns=null`, and an unattempted removal whose original job deadline has expired. It does not fabricate a remover PID, failed claim or old removal deadline. Explicit None cannot bypass an existing/unknown/closed/retired claim or lost provenance.

1. Compare the exact current quarantine, lane occupant, generation and all retained original anchors, plus either the exact current claim object or every initial-transfer condition above. Require failed/non-success capture/removal disposition, qualified exit of every capture/removal writer ever attempted, no identity loss or unknown process, and no other current user. A recorded attempt that never reached spawn can retire without a remover PID; unknown spawn cannot. Merely receiving a report or signal result cannot satisfy this gate.
2. The recipient acknowledges ownership of the same live quarantine, original FDs, latch and prior claim/process/deadline history. Until that acknowledgment is installed, the sender remains owner and its failed claim remains current, or the initial generation remains unclaimed. Rejection, capacity failure or exception leaves every original owner/generation/claim unchanged; no released FD, new writer or permit is allowed. The fixed holder operation must not perform external I/O or invoke arbitrary code between validation and commitment.
3. For retry, mark old claim A permanently transferred/retired and record its original failed disposition, deadline and confirmed exit without rewriting it as successful removal. For initial transfer, record only the genuine capture debt, original job deadline or null, and a consumed initial-transfer event; there is no old remover A to retire.
