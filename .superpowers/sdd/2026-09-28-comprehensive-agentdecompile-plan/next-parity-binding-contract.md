Date: 2026-10-02. Status: **P1 below is ready for implementation; qualified target-region parity and the accepted-source adapter are not ready to claim.** This is a source-only contract. No checker, compiler, import, test, build, database, catalog or runtime operation was performed.

## Source findings that determine the contract

Source references are repository-relative; symbol names are the stable locators.

- `grid_lanes/parity.py:ParityCheck.run/verify` currently labels sides with requested refs, materializes through `_common.materialize_object`, and compares only recomputed receipt refs. It does not hash the actual materialized input bytes, authenticate proposed receipt/raw bytes, or bind the proposal's own task ID and basis to the passed spec. `ResultStatus.OK` means an observation was produced; a receipt can still have `grade=error`.
- `_common.materialize_object` can use arbitrary `get_path` or unbounded `get`. `LocalDirStore.get_path` defaults to a hard link. A checker must never receive a writable alias of stored input bytes. `LocalDirStore.get` can quarantine or touch the store on read. Neither helper is the bounded, independent, nonmutating input route required here.
- `register_native` pins only native executable bytes. `register_node` pins the script, `dist/objdiff.js`, and `dist/objdiff.core.wasm`, in that order; it omits the Node executable. `resolve_checker` returns the cached registration without rereading the files. `ParityChecker.env()` inherits the host environment. Registration IDs are declared-artifact identities, not qualified runtime closure identities.
- `objdiff_verification.parse_objdiff_report` recursively collects present `match_percent` values only for code/function/instruction-bearing entries. Malformed values are skipped. It does not reconcile section/symbol/byte/relocation inventories. A present 100-percent subset can therefore receive `matched` without proving completeness. `is_objdiff_match` deliberately accepts weaker code-slice statuses elsewhere; changing that generic predicate would be an unrelated behavior change.
- `scripts/recovery-toolchains/objdiff-check.mjs` chooses the first visible candidate function if no symbol was requested. It compares one symbol's display rows, suppresses row retrieval exceptions, and can compare two empty/default rows. It does not compare all functions, data, unwind/TLS metadata or relocation inventories. Its printed version is informational. The inspected tracked helper/package references provide **no fixed objdiff release/schema version or Node version pin**; runtime content registration is the existing pin. No installed bundle/version was inspected.
- Native `ParityChecker.argv` ignores `symbol`; Node passes it. The receipt's requested symbol is therefore a task binding, not proof of native symbol filtering or Node scope completeness.
- `_common.run_argv` bounds process duration but `communicate()` accumulates unbounded stdout/stderr and permits an extra termination grace period. A size check after it returns is not bounded capture.
- Current `MkobjTarget` has a real positive producer, but v1 is specifically `reference-free-only-v1`, a single raw-backed PE function, with a declared Python source closure. It is not general relocated-object production, qualified runtime, or current admission. The reviewed target changes `24d3547f` + `2472d02b` and compile binding `d966fefc` do not activate or admit anything by themselves.
- `corpus/coff_fixup_roundtrip.py` supplies real `parse_object`, `place`, `roundtrip_region`, and `check_replacement` interfaces. The parser selects one code section and omits other sections from its returned comparison model. These are useful region/fixup components, not an exhaustive object inventory authority. `verify_recovered_byteexact.text_bytes_and_relocs` selects the first text section; its relocation-masked equality is explicitly diagnostic.

Read with `next-parity-binding-slice.md`, `next-acceptance-adapter.md`, the U11/U4 extracts, and STRATEGY's scaffold/local/linked/whole-image distinctions. Earlier adapter wording “full target-object parity” must mean the complete declared emitted target-region closure, with non-load-bearing object metadata explicitly classified; it must not be implemented as raw whole-COFF equality.

## P1: exact operation

1. **Validate before I/O.** Require the selected kind/version, `SMALL` budget, nonempty string basis, valid SHA-256 refs for exactly `target` and `candidate`, a full native/Wasm ID with a lowercase 64-hex suffix, and an optional string symbol of at most 4096 UTF-8 bytes without NUL. Allow only existing parameter names `verifier_id`, `symbol`, `timeout_s`. Omitted or null symbol retains the existing empty-string meaning. Preserve the existing finite timeout default/cap semantics (omitted/null/nonpositive means 60 seconds; positive values cap at 60); reject booleans, nonnumeric and nonfinite values. Do not add a mandatory capability requirement that changes historical task identity or invent a corpus/source association: this task only names two objects.
2. **One deadline.** Start a monotonic 60-second maximum operation deadline before evidence I/O. Verification's proposal reads, checker revalidation, independent execution, rereads and publication share that deadline; the recomputation does not receive a fresh full budget. Check it between bounded chunks/stages and pass only the remaining budget to the subprocess. This is cooperative local-file I/O bounding plus subprocess enforcement, not a guarantee against a kernel filesystem stall; owner admission must provide a suitable local filesystem.
3. **Bound actual reads.** Set fixed initial limits: 64 MiB per object input, 1 MiB canonical receipt, 4 MiB raw stdout, 1 MiB stderr, 256 MiB per declared checker artifact, 64 KiB chunks. These are implementation constants, not caller overrides. Refuse over-limit material before parsing; never truncate and accept. The candidate/object cap matches the existing local COFF diagnostic reader's ceiling and is a support bound, not evidence of complete parsing. Check declared size, then read no more than limit+1 bytes from a descriptor opened below the local store root without following shard/object symlinks. Require a regular file, authenticate the actual stream against its ref, and check stream size against the declared size. Do not invoke quarantine, touch-on-read, garbage collection, or named-pointer writes. Missing/inaccessible evidence differs from observed corruption.
4. **Own scratch.** Use a fresh private `TemporaryDirectory` under the passed scratch root for each invocation. Copy inputs to exclusive-created ordinary files; no hard links, store-supplied destination reuse, or traversal through caller-controlled child names. The checker sees only these independent named copies. Rehash both just before launch and after exit, requiring the original refs and sizes. The same before/after check applies to declared checker artifacts. A detected change invalidates the observation; publication happens only after checks. Endpoint hashing detects persistent changes, not hostile change-and-restore during execution; qualified immutable-runtime admission remains separate.
5. **Revalidate the existing checker ID.** Resolve once, record the exact resolved files, and recompute the existing registration formula immediately before execution and after it. Native: executable SHA-256. Node: ordered script/js/Wasm digests using the existing formula. Compare against the spec, not merely the cached object's ID. Missing files are unavailable; changed declared bytes are checker-identity mismatch. Resolve the Node executable path once to avoid further PATH selection during this operation, but do not claim it is pinned by the existing Wasm ID. Preserve the existing actual checker invocation and environment in P1; do not describe inherited environment or omitted runtime dependencies as qualified.
6. **Bound subprocess capture.** Use a lane-local bounded capture path that drains stdout/stderr concurrently, reads at most each limit+1, and terminates/reaps only its own newly created process group on deadline/overflow. No output-limit decision after an unbounded `communicate`. Reserve any termination/reaping grace within the operation deadline; report execution unavailable if clean reaping cannot be established. Do not kill unrelated processes. Retain raw stdout using exactly the existing decoded/re-encoded UTF-8 replacement convention. Stderr remains a digest/metric, never alternative match evidence. This is a real invocation of the resolved checker, not a stub or generic caller-selected provider.
7. **Build and authenticate outputs.** Factor the existing receipt construction into one deterministic lane-local normalizer: selected parser, removal of `output`, exact kind/version/ID/flavour/sides/requested symbol/basis, `grade=status`, and current message scrubbing/portability rule. Preserve its emitted byte shape. Require `objects.put` return exactly `ObjectRef.of_bytes` of the canonical receipt and raw bytes supplied; then bounded-reread both retained objects and authenticate them before returning. An existing corrupt CAS entry must not pass merely because `put` returned its expected name.
8. **Authenticate the proposal before recomputing.** Require `result.task_id == spec.task_id`, `result.basis_hash == spec.basis_hash`, `status == OK`, empty reason, and exactly `receipt`/`raw` outputs with valid refs. Authenticate both actual objects with the same bounded route. Parse canonical receipt JSON with duplicate-key and nonfinite-number rejection; reject malformed or noncanonical receipt bytes. Require known schema/kind/integer version, exact sides/ID/flavour/requested symbol/basis, `grade == status`, and a valid parser-shaped grade/differences/exit combination. No caller metrics fill missing binding.
9. **Raw evidence is load-bearing.** Parse the authenticated proposal raw text using the bound checker flavour and the receipt's strictly typed integer `objdiffExit`; reapply the same normalizer and require the exact canonical proposed receipt bytes. Then execute independently under the same selected spec, authenticate that result with the same output-binding helper, and compare the canonical receipts. Raw refs need not equal between runs because helper stdout includes scratch paths; each run must independently bind its own raw bytes to its normalized receipt. Exit status in proposal JSON is not trusted as observed until independently reproduced receipt equality. A matching receipt paired with unrelated raw stdout must be refuted.
10. **Emit the precise verification.** Only a successful complete authentication/recomputation returns VERIFIED. Its evidence contains `predicate="authenticated-checker-observation-v1"`, `comparison_scope="native-reported-code"` or `"node-reported-symbol-rows"`, `checker_identity_scope="registered-artifacts-v1"`, `target_region_complete=false`, `runtime_admission="not_evaluated"`, `grade`, and `compared=["receipt"]`. Reference both proposal and recomputed output refs in the existing evidence style. These scope fields are conclusions of this implementation, not input flags. For node empty-symbol selection they intentionally do not invent the resolved symbol identity. A later qualified scope requires a separate versioned predicate.

P1 must not compare target and candidate raw object hashes for equality. Input digests identify the two different objects; objdiff remains the actual observation. Successful diagnostic reproduction is useful even where their COFF metadata differs.

## P1: outcomes and stable reasons

Use one evidence `reason` with the following stable values; optional `role` is one of `target`, `candidate`, `receipt`, `raw`, `checker`. Run-time refusals use the same value with `parity_` prefix. Do not serialize filesystem paths or exception text into reasons.

| Condition | Verification outcome / reason |
|---|---|
| Unsupported/malformed selected task, timeout representation or support bounds | UNVERIFIABLE / `invalid_spec` or `limit_exceeded` |
| Unsupported store/platform | UNVERIFIABLE / `transport_unsupported` |
| Missing/inaccessible input or proposal evidence | UNVERIFIABLE / `input_unavailable` or `proposal_unavailable` |
| Observed selected-input digest/size contradiction | UNVERIFIABLE / `input_integrity_failed` (cannot execute the selected task) |
| Wrong proposal task/basis/status/output set, malformed receipt/ref, proposed digest contradiction, raw/receipt contradiction | REFUTED / `proposal_binding_invalid` |
| Missing checker or unreadable declared artifact | UNVERIFIABLE / `checker_unavailable` |
| Current registered-artifact formula differs from selected ID | UNVERIFIABLE / `checker_identity_mismatch` |
| Owned inputs/checker change during independent execution | UNVERIFIABLE / `execution_changed` |
| Capture exceeds limits, deadline expires, invocation/publication fails | UNVERIFIABLE / `output_limit_exceeded`, `deadline_exceeded`, or `execution_unavailable` |
| Independent produced output fails local authentication | UNVERIFIABLE / `recomputed_binding_invalid` (do not penalize the proposal for verifier failure) |
| Two authenticated canonical receipts differ | REFUTED / `receipt_differs` |
| Two authenticated canonical receipts agree | VERIFIED / `receipt_equal` |

An over-limit proposal is UNVERIFIABLE, not automatically malicious: the bounded verifier cannot inspect it. A malformed/inconsistent proposal actually read within the supported bounds is REFUTED. Unexpected local parser/I/O failures are unavailable, not matches.

Keep three positive result classes: reproducible `matched` observation; reproducible `mismatched` observation; reproducible `error` diagnostic. All can be VERIFIED **as observations**. None supplies `byte_exact_source`; `grade=error` never becomes successful parity. Checker nonzero exit is retained according to its current parser rules (native error, Node exit 1 mismatch); subprocess timeout/capture failure produces no verified observation.

## Named positive and refusal cases for later authorized verification

- `node_executable_changed_outside_id`, `inherited_environment_changed`: P1 must still state only registered-artifact identity and no runtime admission. These are mandatory refusal cases for future qualified closure, not a falsely advertised property of this legacy ID.
