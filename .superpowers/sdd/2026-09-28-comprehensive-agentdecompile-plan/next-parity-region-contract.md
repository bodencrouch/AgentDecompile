# P2: complete reference-free emitted-region comparison

Date: 2026-10-02. **Implementation-ready source contract; not implemented, executed, installed, qualified or admitted.** Own only this document. P1's adopted `next-parity-binding-contract.md` remains its stable interface; its v1 tasks, receipts, verifier IDs and eight-column view do not change.

## Decision and exact claim

Add one separate `parity-region-check` v1 lane with verification method `parity-region-coff-i386-leaf-v1`. It consumes and actually re-verifies a `mkobj-target` proposal and a native `parity-check` proposal, inventories both authenticated COFF files exhaustively, checks a small explicit instruction language on both complete regions, strictly validates the pinned native report, and compares every region byte. Its positive claim is **byte equality of the complete declared reference-free emitted region under the named policy**. No byte mask, omitted tail, selected display subset, raw whole-object equality, JSON success flag or caller-selected predicate may establish this claim.

The initial support profile is `objdiff-3.8.0-native-linux-x86_64-coff-i386-leaf-v1`. The checker host is Linux x86-64; the compared object machine is **i386**, not x86-64. The deliberately narrow instruction/object subset has real positive members. Broader reference-free functions, x64/other architectures, relocated targets, COMDAT and associated data/unwind/TLS handling require later explicit policies. Unsupported does not mean unequal, unsafe, or unrecoverable.

This predicate does not establish candidate source identity, compiler contribution, ABI equivalence, current trust/admission, ambient image metadata equivalence, linked-region replacement, whole-image recovery or runtime readiness. It supplies the complete **local emitted-region** edge to the subsequent compile/source join and P3 admission. STRATEGY's linked-region and fresh whole-image gates still apply.

## Exact reference-free instruction language

Policy `coff-i386-register-leaf-v1` accepts a nonempty, at-most-64-KiB region parsed from offset zero to its exact length by this finite grammar:

```text
region := body C3
body   := instruction* zeroEax instruction*
instruction := 90 | 31 C0 | 33 C0 | 40 | 48
zeroEax := 31 C0 | 33 C0
```

Equivalent implementation: scan using a table of exactly those encodings; require at least one zero-EAX operation, exactly one `C3` at the final byte, and no other instruction/byte. `90` is one-byte NOP, `31 C0` and `33 C0` are the two register-direct XOR-EAX-with-itself encodings, `40` is INC EAX and `48` DEC EAX in **32-bit mode**. There are no prefixes, immediate constants, ModRM variants, memory accesses, stack adjustments, local/direct branches, indirect call/jump, far return, `ret imm16`, or trailing code/data/padding. Only near RET implicitly consumes the ordinary caller return address. Do not decode `40/48` as standalone instructions in x64; x64 refuses before decoding.

The scanner emits every `(offset, length, encoding, operation)` in order. The sum of lengths must equal the section size; every offset belongs to exactly one token. Independently scan both sides; subsequently require exact byte equality, not merely equal tokens or behavior. Thus `31 c0 c3` and `33 c0 c3` may express the same operations and receive a favorable checker observation, but must not satisfy P2 byte equality. Positive examples include `31 c0 c3`, `33 c0 40 c3`, and `90 31 c0 40 48 c3` when each target/candidate pair has identical bytes.

This conservative first grammar intentionally refuses most real functions, including safe register MOVs, stack prologues, integer immediates, direct internal branches, and x64 leaf functions. It does not classify those as mismatches. It supports ordinary zero/near-zero scalar-return leaf implementations without pretending to solve general reference discovery. Candidate semantic/source meaning and calling convention remain later joins.

In particular, `b8 10 20 30 40 c3` (`mov eax,0x40302010; ret`) refuses even if no relocation exists: an immediate can be an address-valued constant. The first policy admits no immediate operands at all, so it does not require a permissive address-range guess or a post-hoc caller assertion that a constant is harmless. Returning a computed integer is not a proof of its caller's semantic interpretation; semantic identity and runtime callable claims remain excluded.

## Exhaustive COFF inventory and complete region association

Implement a new independent byte parser in `grid_lanes/parity_region.py`; do not use `coff_fixup_roundtrip.parse_object` or `text_bytes_and_relocs` as an inventory authority because they select a text section. The standard layout reference is Microsoft's [PE/COFF specification](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format). The stricter acceptance policy here intentionally supports fewer layouts than COFF permits.

Read the entire object into an immutable bounded byte value once through authenticated descriptor I/O. All arithmetic is checked before slicing or allocating; a count multiplied by record width must fit the actual file and caps. Reject unsupported encodings before interpreting their fields. Inventory **every** header, section, primary/auxiliary symbol, string, relocation declaration, line-number declaration and byte interval, even if later refused. No section-name prefix or ignored/debug flag grants exclusion.

| File form/header | Standard little-endian 20-byte COFF header; machine `0x014c`; exactly one section; optional-header size zero; file characteristics `0` or `0x0100` (redundant i386 indicator only). No PE, archive, import object, anonymous/bigobj, LLVM bitcode/LTO, executable image or unsupported machine. Timestamp is recorded but not compared. |
