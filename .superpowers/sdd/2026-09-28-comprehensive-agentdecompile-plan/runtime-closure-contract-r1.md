# P3.2: captured native execution closure

Date: 2026-10-02. **Revised proposed source contract; controller adoption pending.** Only this report was edited. No host capability, root, key, configuration, installed runtime or successful execution was inspected or provisioned. This is neither a P3.1 authentication change nor a replacement P2 predicate. The first implementation slice is exactly qualified **P2 verify**, with deferred local signing guarded at the actual seal. A separately versioned future reader is required for current admission; execution/collection alone cannot claim end-to-end acceptance.

## Decision and trust boundary

Implement one `linux-x86_64-native-objdiff-region-runtime-v1` profile using the existing sandbox/job lifecycle, a **private supervisor-owned byte-copy capture**, and a pinned non-setuid bubblewrap launcher. The child sees that capture read-only, with a separate job-local writable `LocalDirStore`. The profile requires an owner-provisioned private work filesystem with `noexec,nosuid,nodev`; it does not silently substitute bubblewrap's ordinary `--tmpfs`. No new privileged setup helper, OCI manager, Docker/Podman adapter or general policy language is proposed.

The owner, configured Linux kernel, supervisor/collector implementation, its launcher and its selected verifier implementation are trusted. Operator-selected runtime bytes are trusted to implement their advertised semantics once their identity is established. Tasks, proposals, snapshots, COFF inputs, worker-reported closure claims, mutable donor trees and unrelated writers are untrusted. The owner selects the predicate whose actual execution is attested; there is no hardware attestation or protection from a malicious owner or deliberately malicious admitted verifier. Native memory corruption in an admitted interpreter/checker is not proved absent by this profile. This distinction is necessary: an interpreter permitted to read task data can interpret those bytes if its own code deliberately does so; mount flags cannot decide Python code versus data.

The supervisor's host identity must exclude unrelated unconfined writers. A dedicated owner-configured UID with private directories is a concrete first supported arrangement; all processes with that host UID outside the confined children belong to the trusted supervisor domain. `0700` alone does **not** exclude another hostile process with the same UID. Confined children may map that UID, but receive no host directory, parent-namespace process handle, network connection, signing credential or writable runtime inode. An installation sharing this UID with unrelated unconfined workers refuses `supervisor_domain_unavailable`. This is a real deployment premise, not permission to create a service account now.

The claim is: the actual selected operation ran under one measured executable/import/configuration view, enforced for its lifetime, and the resulting exact verification/evidence tuple was collected by the trusted supervisor and independently signed. It is not a claim that every file in the complete allowed root was loaded, nor that tracing one sample's loaded files establishes the complete closure.

## Root artifact, capture and complete inventory

The configured root is a local **donor artifact**, never directly the execution mount. `profile.json` is owner-pinned by content digest and contains schema/profile version, expected root inventory digest, implementation source digest, interpreter path/version family, fixed entrypoint, exact checker ID/path, launcher identity, confinement policy identity, fixed environment and the supervisor-domain/work-filesystem requirements. It contains no private keys. The task may select only the configured profile ID; it cannot change any path or policy.

Root inventory v1 is canonical JSON listing every directory, ordinary file and safe symlink beneath the selected artifact. Entries bind relative path, type, executable permission class, size/hash or symlink target. Reject duplicate/absolute/parent-traversing paths, special files, mount crossings, writable executable permissions, set-ID modes, capability/security xattrs, dangling/cyclic symlinks and links escaping the final root. Source hardlinks are rejected; capture does not preserve inode aliases. Do not extract a caller-supplied archive or run installation hooks. Max inventory 8 MiB, 16,384 entries, path 512 UTF-8 bytes, depth 24, 256 MiB per file, 1 GiB total file bytes, 64-KiB streaming chunks. Limits are profile constants, not task overrides.

Suggested fixed root layout:

```text
/usr/bin/python3.12                 exact configured CPython ELF
/usr/lib/python3.12/**              source stdlib and matching lib-dynload
/lib/**, /lib64/**, /usr/lib/**      exhaustively inventoried ELF dependencies
/app/src/agentdecompile_grid/**     exact grid source, including bootstrap support
/app/src/agentdecompile_recovery/**  exact recovery source and transitive local imports
/app/vendor/**                     explicitly included third-party Python packages
/app/native_closure_entry.py        fixed measured entry shim
/tools/objdiff                      exact official P2 native asset
/etc/**                            only explicit measured configuration, if needed
/work                              empty mount point
/dev/null                          mount point, not a device copied from the artifact
```

The interpreter family choice is CPython 3.12 for this first profile, not a claim about this host. Exact patch/build bytes, libpython if used, extension modules and compatible libraries are owner-pinned in the complete inventory. A captured installation must resolve the stated prefix/layout without a host venv, `pyvenv.cfg`, system site packages or editable install. If the selected artifact cannot do that, it is unsupported; do not synthesize a successful inventory from import errors. The package initializer imports more than the three exercised lanes, so include their actual transitive import bytes, even where a module's other operations are never invoked. Do not infer the closure from three filenames or a successful startup sample.

The supervisor creates a fresh private capture under its protected runtime filesystem using descriptor-relative, no-follow opens and exclusive destination creation. It copies bytes (no hardlinks, bind donors, reflink dependency, archive extraction or mutable shared cache), hashes the **copied** bytes, closes every writable capture descriptor, validates the complete destination inventory, compares its digest to the owner pin, removes write permission and retains directory descriptors for launch. Pinning the expected inventory catches torn/mixed donor generations. Post-capture donor edits cannot affect these distinct inodes. The supervisor alone can modify this host capture and promises not to until the job tree is gone; the child view is recursively read-only with no writable alias. This suffices under the stated supervisor trust boundary; protection from the trusted owner itself is not required.

Capture may later be reused only as a still-owned immutable captured instance with the same pin and no exposure of write handles, not as a caller's existing directory named by a digest. A fresh bounded verification of destination identity is required for a recovered supervisor after a crash. No launch from an unverified mutable donor.

## Fixed confinement and loading rules

Use the owner-pinned, non-setuid bubblewrap **v0.11.0 source contract**, with exact installed launcher bytes separately pinned; a version string is insufficient. The launcher and its host-loaded dependencies belong to the trusted supervisor boundary and owner configuration, not to worker-authored evidence. A profile cannot claim to measure a malicious supervisor by hashing files beside it.

The launch vector is constructed internally: explicit user/PID/IPC/network/UTS namespace isolation, read-only captured `/`, bind only the private noexec job directory at `/work`, one `/dev/null`, fixed cwd `/work/scratch`, fixed numeric inherited IPC descriptors, `--clearenv`, `--cap-drop ALL`, `--disable-userns`, `--new-session`, `--die-with-parent`, pinned seccomp filter and status/sync descriptors. Do not use `--*-try`, `--unshare-all`'s optional behavior as proof of required support, host `/proc`, host `/sys`, host `/tmp`, host home or broad `/dev`. The child needs no procfs for the real target/P1/P2 path; outside supervision can use its owned process handles. Reject a dependency that unexpectedly requires these mounts.

The work source must already be on an owner-provisioned `noexec,nosuid,nodev` filesystem with a hard 1-GiB allocation bound for this single job. The supervisor validates the mount identity/flags before launch and confirms the actual child's mount view at the startup barrier. A writable donor tree or ordinary executable `/tmp` is not equivalent. Bubblewrap's v0.11.0 `PRIV_SEP_OP_TMPFS_MOUNT` uses `MS_NOSUID | MS_NODEV` without `MS_NOEXEC`; therefore this design does **not** use its plain tmpfs as executable-exclusion evidence. Its source also exposes required namespace/FD hooks. [Versioned bubblewrap source](https://raw.githubusercontent.com/containers/bubblewrap/v0.11.0/bubblewrap.c).

Noexec blocks native execution and executable mappings of files in `/work`; it does not prevent Python reading a script. Linux documents `mmap(PROT_EXEC)` failure on a noexec filesystem. [Linux mmap manual](https://man7.org/linux/man-pages/man2/mmap.2.html). Hence all of the Python rules below are necessary as well.

The fixed x86-64 seccomp program denies non-native syscall architectures and x32; `unshare`, `setns`, namespace-bearing `clone`; mount/view changes (`mount`, `umount2`, `pivot_root`, `chroot`, `open_tree`, `move_mount`, `mount_setattr`, `fsopen`, `fsconfig`, `fsmount`, `fspick`); `ptrace`, `process_vm_*`, `pidfd_getfd`, `open_by_handle_at`, `memfd_create`, `execveat`, `bpf`, `perf_event_open`, `userfaultfd`, `io_uring_*`, `shmat` and socket creation/connect/listen/accept. `clone3` returns ENOSYS so libc may use supported clone. Existing inherited IPC uses read/write/sendmsg/recvmsg; it needs no new socket. Deny executable anonymous or writable `mmap`, and any `mprotect`/`pkey_mprotect` request adding PROT_EXEC. Reject executable-stack ELF artifacts. Permit ordinary process creation without namespace flags because the actual P1 checker uses `Popen(start_new_session=True)`; permit `setsid` and ordinary wait/signal operations. Noexec work plus the only executable files being immutable root files closes the file-backed executable mapping path. These are fixed source-reviewed rules, not user-supplied BPF or a syscall-learning success mode. Linux seccomp cannot inspect pointed-to filenames; never express path enforcement as a pathname comparison in BPF. [Kernel seccomp documentation](https://docs.kernel.org/userspace-api/seccomp_filter.html).

The child starts exactly `/usr/bin/python3.12 -I -S -B /app/native_closure_entry.py`. Its measured shim replaces `sys.path` with the fixed root stdlib, lib-dynload, `/app/src` and `/app/vendor` paths before importing recovery. No empty path, cwd, writable directory, zip import, `.pth`, user site, `sitecustomize`, environment expansion or arbitrary plugin discovery is supported. Exclude all `.pyc`/`.pyo` from the captured Python source trees so source-to-loaded binding cannot be defeated by a stale timestamp cache; `-B` alone only disables bytecode writes. Builtin/frozen CPython modules are bound by interpreter bytes. `-I` excludes unsafe/user paths and Python environment variables; `-S` disables automatic `site` processing. [Python command-line reference](https://docs.python.org/3.12/using/cmdline.html).

Environment is constructed from scratch: `PATH=/tools`, `LANG=C`, `LC_ALL=C`, `TZ=UTC`, `HOME=/work/home`, `TMPDIR=/work/tmp`, `AGENT_DECOMPILE_OBJDIFF=/tools/objdiff`. No inherited `LD_*`, `GLIBC_TUNABLES`, `GCONV_PATH`, `LOCPATH`, Python variables, certificate variables, XDG/config home or job `env_extra`. The job ID travels in private IPC, not as an authority-bearing environment string. Root `/etc/ld.so.preload` and loader cache are absent in this profile; loader default paths, any RPATH/RUNPATH and all potentially selected library variants must resolve within inventoried root directories. Reject writable/relative/cwd loader search paths. `/work` has no import or configuration search role. Objdiff receives exactly P1's existing explicit no-project argv; no project configuration or shell is consulted.

The complete root binds interpreter, stdlib, native modules (`_sqlite3`, hashing modules, etc.), linked SQLite and all recursive ELF loader/library dependencies. Do not run `ldd` over untrusted input to construct it. A bounded static ELF dependency inventory and the complete captured filesystem establish the allowed loading universe; missing dependencies refuse during separately authorized fixture qualification. Startup and final module diagnostics bind `__spec__.origin`, loader class and `__file__` to inventoried paths, with builtins/frozen modules classified separately. They are diagnostics corroborating the enforced root, not proof from before/after file hashes. The actual target helper reconciliation remains mandatory. No input contains source to `exec`, `eval`, pickle, dynamic module selection or a native extension path; SQLite extension loading remains disabled.

Do not claim that a Python-level audit hook establishes confinement against hostile Python. Python explicitly says such hooks are bypassable and unsuitable as a sandbox. An optional import audit can diagnose violations, but authority is the admitted fixed entrypoint/import behavior plus immutable root and kernel confinement. [Python audit-hook documentation](https://docs.python.org/3.12/library/sys.html#sys.addaudithook). If protection against intentionally malicious admitted Python/verifier code is demanded, this profile is insufficient; that is a different architecture, not a missing flag.

## Private actual job identity and independent collection

The supervisor creates a 256-bit nonce, unique job directory and one-use launch-handle object before launching. The handle binds profile/capture/policy, exact canonical task and selected proposal digest, basis, op, intended signer role/key ID, deadline, owned launcher PID/start identity and private IPC endpoints. These values never come from child claims or a recovered `result.json` filename.

V1 uses exactly an inherited anonymous Linux `AF_UNIX/SOCK_SEQPACKET` socketpair, nonblocking, with `SO_PASSCRED` on the supervisor receiver. No pipe fallback. Child control FD is 3; launcher status FD 4, lifecycle-sync FD 5 and hashed seccomp-input FD 6 have separate ownership and are not control messages. Initial `Popen(pass_fds=...)` inherits only those descriptors plus bounded stdio. The fixed shim makes FD 3 close-on-exec and closes remaining nonstdio descriptors before P1 launch. Pass no donor/directory/signing FD. Kernel `SCM_CREDENTIALS` on **each** child frame must identify the same actual outer Python PID/UID/GID; pre-fork `SO_PEERCRED` is not sender proof. [Linux UNIX socket credentials](https://man7.org/linux/man-pages/man7/unix.7.html).

Frames are canonical strict JSON objects with exactly `{schema:"agentdecompile.native-region-ipc.v1",kind,nonce,seq,payload}`; seq is an integer starting at zero per direction, never bool, increasing by one. Datagram cap 64 KiB including envelope; metadata strings ≤256 bytes except fixed digest strings. Nonce is the launch handle's 64-hex token. Protocol states are supervisor `await_hello -> check_ready -> send_start -> await_completion -> closed` and child `hello -> ready -> await_start -> run -> complete -> closed`. HELLO payload is exactly `{profile_id}` (≤2 KiB frame), READY exactly `{profile_sha256,root_sha256,filter_sha256,entrypoint_sha256}` (≤4 KiB); reported identities must match supervisor evidence and are not self-attestation. START carries exactly `{task_ref,result_ref,plan_sha256,verifier_key,deadline_remaining_ms}` (≤4 KiB), referring to already staged data. COMPLETE metadata is exactly `{verification_ref,verification_size,module_diagnostics_ref,module_diagnostics_size}` (≤4 KiB); the completion V0 is read and authenticated from the private job store after tree termination, capped at 1 MiB, so large socket fragmentation is unnecessary. No arbitrary ref in this metadata is followed unless it is the fixed named completion object and matches the retained tuple/schema. No heartbeat or additional message type. Reject unexpected order, duplicate/truncated frame, EOF before COMPLETE, differing credentials/nonce, ancillary descriptors or oversized data; close received SCM_RIGHTS FDs before refusal.

Pidfds for both namespace init and entrypoint are **mandatory**. Pin launcher process ownership from spawn. Read its ≤64-KiB status channel and obtain the actual namespace-init outer PID; acquire its pidfd while still anchored to the owned launcher. HELLO's kernel sender PID supplies the separate entrypoint pidfd. Before release, check bounded owner-readable `/proc` data for init/entrypoint start identities, direct parent/namespace association, expected UID/GID, namespace IDs, entrypoint executable and exact argv, root/captured inode identity, read-only root/noexec bounded work mount view, no forbidden mounts, no-new-privileges/seccomp state and actual hard limits. Bound each proc read to 64 KiB, aggregate 512 KiB. Keep the process paused at READY throughout checks; recheck pidfd liveness/identities immediately before START. Unavailable pidfds or access-denied identity/root reads yield `owned_process_identity_unavailable`; child self-reports never substitute. `/proc/PID/root` has ptrace-style access checks, so availability is a genuine later host premise. [Linux process-root access](https://man7.org/linux/man-pages/man5/proc_pid_root.5.html).

The filter comes from the parent-held hashed FD consumed by the pinned launcher; its mandatory install-failure path aborts startup. A `/proc` enabled bit alone does not identify BPF bytes. READY is emitted only after the fixed shim has set/checks its hard limits and fixed imports. No task bytes are parsed before START. Launcher setup status or `--block-fd` release is not this Python-ready barrier. These later authorized owned-process observations were not performed during this report.

After COMPLETE, authenticate the exact V0 and all fixed output/evidence refs only after the tree is gone: 128 exports/64 MiB aggregate, retaining individual caps. Inputs already authenticated in the trusted source store need not be copied back. Every put and bounded reread must agree with actual stream hashes. Reserved child `execution_binding` fields, store named pointers and foreign refs cannot supply authority. Supervisor consumes the live launch handle once; no serialized JSON reconstructs it.

## Exact evidence DAG and separately versioned current-P2 reader

All schemas below reject unknown/missing/duplicate fields and noncanonical JSON. `Hash` means exactly 64 lowercase hex characters, `Ref` means `sha256:` plus Hash, `Id` means a nonempty UTF-8 string ≤256 bytes, and `UInt` means an integer ≥0 excluding bool. V1 caps are fixed, never caller overrides.

`V0` is canonical `worker.records.verification_to_record` **after** the single empty-key normalization: exact fields `{task_id:Hash,result_ref:Ref,outcome:enum,verifier_key:Id,method:Id,evidence:object}`, at most 1 MiB. Only `VERIFIED` with the actual P2 method and exact P2 successful evidence shape can enter the positive qualified seal path; `REFUTED`/`UNVERIFIABLE` remain diagnostic in this first slice, without a qualified positive or infrastructure penalty. ## Actual delayed seal, local durability and restart

Collection captures a coherent owner-authority identity A0 and compares it with launch A0, but **does not sign**. It queues the exact immutable exports, V0/C/E and expected VERIFIED body in the existing outbox plus an in-memory `QualifiedSealToken` keyed by pending-body digest and supervisor boot nonce. The token arises only from this completed live handle, survives retries only within that supervisor process and is not serialized as reconstructable authority. Keys stay outside the child.

First support is only the trusted supervisor-owned durable local immutable CAS and local `transport.local.ChainAppender`. Collection authenticates and fsyncs all required transitive evidence objects before queueing the record. The qualified outbox branch verifies the complete required object set, never takes `same_store`, `exists` or `_confirmed` as fresh content authentication, and neither uses remote transport nor publishes a qualified named pointer before the record. Bounded rehashes at seal authenticate the persisted exact tuple; inability to complete them makes the attempt unavailable. Existing object immutability/durability is a trust premise only after this actual authentication under the protected supervisor domain.

Install a fixed `QualifiedNativeRegionSealGuard` at `ChainAppender.build`, immediately before each qualified `signer.sign` inside **every** `write_batch` retry. It is configured by the qualified local supervisor path, not a caller callback. Reject a qualified E schema if the guard/token is absent. Guard verifies live token/boot identity, canonical pending-body digest, exact C/E/export refs, unconsumed event identity and current effective authority freshly reloaded from owner config. It requires unchanged admission generation/profile/pins plus eligible independent producer/verifier/operator/ancestor keys. Public authority read is coherent: read configuration revision and pinned snapshot/key/revocation bytes under bounded no-follow reads, hash them, re-read relevant identity/pins, reject concurrent change; no indefinitely cached `GridConfig`. The successful coherent authority read immediately preceding the seal is the **linearization point**, not collection or enqueue. Later policy changes are handled by the future current reader; no atomicity with arbitrary owner file replacement is claimed.

A failed CAS retry does not consume the token but must repeat fresh guard checks before another signature. Successful append consumes it; an uncertain append first searches the owned local log for the exact signed event/nonce and never blindly re-signs a duplicate. After supervisor restart, all **unsigned qualified** pending entries are quarantined with `qualified_restart_requires_execution`; they cannot regain authority from queue/C/E JSON. This is deliberately not a durable qualified replay protocol.

## Total bounds, cleanup and refusal

One qualified job at a time per supervisor/work filesystem. P2 retains its internal 300-second operation budget and prerequisite reservations. The MEDIUM 600-second outer ceiling begins before any selected proposal/capture/staging read, not after `Popen`. `begin_native_region_verify` creates only an immutable selection seed and captures `admitted_at`; the fixed recovery builder resolves the complete immutable role plan during the bounded stage phase of an already owned `RunningJob`. No filesystem read hidden in synchronous `_make_job` precedes that timer.

| Internal phase (`stage_ms` includes only the first six completed phases) | Ceiling and transition |
|---|---|
| `capture` | 90 s; private capture authenticated/frozen, its writer helper confirmed gone. |
| `stage` | 100 s; recovery builder authenticates selected envelopes and fixed role graph, then copies data-only plan to job store. |
| `launch_barrier` | 20 s; pinned launcher, mandatory pidfds, HELLO/READY validation, then START. |
| `run` | 300 s; actual P2 verify, COMPLETE metadata or failure. |
| `tree_termination` | 20 s; owned entrypoint/init tree and all helper processes confirmed gone. |
| `export` | 40 s; authenticate/export only fixed refs; exporter helper confirmed gone. |
| `collection` | 10 s; exact tuple/C/E construction and live-handle consumption, enqueue unsigned record. |
| `seal` | Remaining ≤20 s within original 600 s; actual guarded local seal/retry. Token expires at the original absolute deadline. |

Each phase has a deadline `min(entry_time+phase_cap, absolute_deadline-reserved_later_caps)`; never borrow later reservations or extend the absolute ceiling on retry. `RunningJob.started_at=admitted_at`. Before slot reaping, `poll()` advances only bounded nonblocking IPC/status operations (≤16 messages and ≤5 ms per call); capture/stage/export I/O uses at most one owned trusted helper **process**, not an uncancellable thread. Helper is fixed supervisor code with only phase-specific descriptor access, no signer or log writer. Cancellation signals its retained pidfd, then confirms exit before changing phase. No asynchronous writer survives successful capture, export, collection or cleanup.

Running states are `capture -> stage -> launch_barrier -> run -> tree_termination -> export -> ready_for_collect -> collected`, with failure edges to `terminating -> quarantined_pending_io|quarantined`. Map active states to protocol `running`/`terminating`/`killing`; return `exited` only from `ready_for_collect`, when the entire owned tree/helpers are gone and bounded export is complete, because existing `_reap` immediately calls collection/cleanup. `collect()` performs no new unbounded copying. A D-state helper yields `kill-failed` and `quarantined_pending_io`: keep its allocation and descriptors ownership record, do not delete/reuse/sign/finalize it, and allow no next writer. Only pidfd-confirmed disappearance permits `quarantined` and bounded cleanup. In-flight kernel I/O may finish before SIGKILL takes effect; never claim that allocation frozen or cleaned while it remains possible. This prevents a surviving helper from mutating anything after **completed** cleanup; there is no impossible promise to synchronously cancel a blocked kernel syscall.

Set both soft/hard resource limits before task admission: core 0 (do not reuse the current `apply_limits` zero-means-unset behavior), NOFILE 128, FSIZE 256 MiB, AS 2 GiB, NPROC 32 under the dedicated supervisor identity, CPU 300 seconds per process. Work filesystem 1 GiB and streamed input/output/log caps are independent of those per-process limits. Logs: 1 MiB each stdout/stderr; launcher status 64 KiB; module diagnostics 1 MiB/8192 entries. This is bounded execution, not a performance target or assurance that every admitted maximum will finish.

Retain bubblewrap's PID-namespace init and sync ownership. At normal entrypoint completion or deadline, stop admitting messages, terminate the owned namespace tree, escalate after at most 5 seconds, and confirm it is gone before accepting/exporting output or deleting resources. Namespace-init exit causes the kernel to kill its remaining namespace processes, including children that called `setsid`; this is the relevant improvement over process-group cleanup. [Linux PID namespace manual](https://man7.org/linux/man-pages/man7/pid_namespaces.7.html). Use pidfds/retained ownership anchors; never signal a reused numeric PID. Bubblewrap monitor exit alone is insufficient evidence that all descendants finished. A D-state process or ambiguous cleanup yields `kill-failed`/`cleanup_incomplete`, quarantines the private job allocation and blocks its reuse; never wait indefinitely, remove a live mount or count a passing payload.
