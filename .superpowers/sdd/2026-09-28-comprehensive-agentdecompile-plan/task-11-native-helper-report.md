## Parent identity, protocol and timing

Preparation is explicitly quiescent and single-threaded, with a20s cooperative ceiling. It may block in kernel filesystem/spawn operations; no thread or active scheduler refill hides that cost. The parent retains allocation before spawn and records the direct unreaped child immediately, then obtains mandatory pidfd and bounded actual `/proc` start/UID/GID/parent/executable/argv identity. Spawn intent is recorded before entering the kernel; an exception without a returned child PID remains unknown process ownership and cannot enter removal. Failure closes the pre-BEGIN channel and retains uncertain process/allocation ownership; there is no numeric-PID signal fallback or PID lookup substitution. The fixed parked helper exits on parent EOF or its own bootstrap/idle deadline without copying.

The local one-use prepared slot expires after30s. `begin_capture` consumes it and accepts exactly the original admitted/absolute nanosecond seed with a600s duration. Capture deadline is `min(entry+90s, absolute-510s)`, retaining every later phase reservation. Begin performs only local metadata validation and one nonblocking datagram send; it does not prepare, open, stat, traverse or load profile contents. Unknown/failed send consumes the slot and cancels. Explicit maintenance can consume and retire an expired idle slot; no scheduler registration is added.

IPC is the separate capture schema, canonical strict JSON with exact fields, bounded preparse depth/members, non-bool UInt, nonce, independent sequence and per-kind/aggregate caps. Every nonempty datagram needs exactly one matching kernel SCM_CREDENTIALS tuple; unknown ancillary data, missing/extra credentials, truncation, rights, stale nonce, wrong sequence or wrong payload fails. Every delivered SCM_RIGHTS descriptor is closed before refusal. CHALLENGE/HELLO/READY bind retained owner values. BEGIN alone authorizes actual primitive work. COMPLETE is provisional metadata with exact pinned counts/totals and root/profile identities, never an ownership transfer.

`CaptureRun.poll` performs at most16 metadata events, conservatively reserves a full frame's bytes even on malformed receive, caps combined reads at64KiB and stops scheduling work after5ms cooperative monotonic budget. It uses nonblocking socket/pipe/pidfd readiness and owned P_PIDFD waitid only; no tree, profile, process-path, spawn, sleep or removal work occurs there. Per-stream diagnostics cap at1MiB and aggregate at2MiB even though bytes are discarded. Lost identity fails even with no ready IPC; bad readiness handles enter finite cancellation. COMPLETE requires matching pidfd exit readiness plus matching nonblocking direct-child WNOWAIT/reap status, exitzero and all control/diagnostic EOFs before phase expiry. Exitwithoutreport, nonzeroexit, duplicate/postterminal frames, unknown identity or late completion cannot promote.

Cancellation immediately invalidates provisional success. TERM and KILL use only the retained pidfd, with5s/5s grace truncated to capture/outer deadlines. Unconfirmed exit yields finite `quarantined_pending_io`/`kill-failed`; root/parent/process/doc anchors and lane occupancy remain retained. Later passive exit observation can enable removal queue admission but never resurrect success. No D-state instant-termination claim exists.

`take_capture` transfers the exact parent-held allocation handles once into `OwnedCapture`, constructs identity from parent pins, retains lane occupancy for the later lifecycle and releases only completed transport descriptors. `take_quarantine` transfers the same live ownership once into `CaptureQuarantine`. Updates contain metadata only. No frame carries a path, FD number, arbitrary ref or ownership document.
