## Finding M1 — diagnostic overflow skips the per-poll byte debit

**Severity: Minor. Confidence: high.** Locations: `src/agentdecompile_grid/worker/native_removal.py:944–952,1133–1154,1177–1182`. Corresponding regression coverage: `tests/test_grid_native_removal.py:974–985,999–1007`.

`_drain_log` performs `os.read` and increments the cumulative stream counter, then raises `RemovalRefused` when that counter exceeds its limit. The caller subtracts from `bytes_left` only through `bytes_left -= _drain_log(...)`. If the call raises after a successful read, the subtraction is skipped. Poll catches the exception, requests cancellation, and continues processing ready sources. Cancellation is correctly idempotent, but it does not end that poll or charge the discarded bytes.

One exact source-only schedule demonstrating the defect:

1. Keep the cooperative clock inside five milliseconds and the helper exit unconfirmed. Give the control endpoint queued malformed 4,097-byte datagrams and both diagnostic pipes queued 4,096-byte reads. Set both existing diagnostic counters to their 1 MiB limit before this poll.
2. Each readiness group is control, stdout, stderr. Each control read reserves 4,097 bytes at line1153 and refuses. Each diagnostic read consumes 4,096 actual bytes but raises at line949 before the caller can debit them. The first refusal starts cancellation; later refusals do not reset it.
3. Five complete readiness groups consume 15 events: five control reads and ten diagnostic reads. The sixteenth event is another control read. The retained byte counter is still positive because it charged only the six control reads.
4. Total actual requested/returned payload bytes are `6 × 4,097 + 10 × 4,096 = 65,542`, exceeding the promised 65,536-byte ceiling by six bytes. This schedule requires no post-terminal success and does not bypass cancellation or the 16-event limit.

The defect is narrow: each event requests at most4,097 bytes and there are still at most16 events, so the excess is small rather than an unbounded drain. It does not grant deletion authority, clear quarantine, permit reuse or qualify a failed helper. That limits severity to Minor, while the literal64KiB contract/report claim is not exact on this exception path.

Suggested remedy for the source owner: reserve the requested diagnostic read cost before calling the fallible drain function, or separate read/debit from cumulative-cap validation so every successful read is charged even when later validation raises. Preserve the existing event/time bounds and nonblocking semantics. Add a paired authored regression combining over-limit diagnostic counters with queued malformed full-size control datagrams and full-size reads from both diagnostic pipes; assert the scheduled/read total stays at or below65,536, cancellation retains the original reason/deadline, and no descriptor/lane release occurs. Existing pressure coverage starts below the log limits; existing overflow coverage supplies only one byte, so neither covers this combination. No reproduction or test was executed in this review.
