# CodeBrowser

The composite center pane: Listing and DecompileView side by side on one cursor, an optional HexStrip beneath them, Graph as an alternative to Decompile, a function Outline popup that follows the cursor, and References placed beside or under the code, so reading code never means flipping analysis tabs.

**Use it** as the center of the Code Browser workspace on both surfaces. It is the one place code is read: the Functions list drives it, the evidence rail follows it, and the dock stays below it.

**Consumer provides** the primary location (project, entity, build, address); the co-visible views (`views=listing,decompile,hex,graph`); the hold state of each center pane (Following, or Held with the held pane's entity × build × address, its read time and basis); Listing rows, decompile lines and bytes from existing analysis, with the listing ↔ decompile mapping; the Outline projection of the current function (basic blocks with line ranges, locals and parameters, calls, strings); and the References rows for the token under the caret.

- **One composite header**, not one per well: the Views toolbar row carries the function name with its NameProvenance tier word, the FactBadge strip as one Peek button, the inspected build and the cursor (address and line); then the Listing · Decompile · Hex · Graph toggles (`aria-pressed`), **Hold this pane** and Outline. Wells keep only their view name and their follow or hold words ("Follows · as I move", "Held · …"). `sticky-offset` includes this row, and below 480px of viewport height only the NarrowFlow bars stick.
- **At most two center panes plus the HexStrip.** Turning on a third center view replaces a named one, never "the pane beside it": Graph replaces Decompile, Decompile replaces Graph, and Listing replaces Graph. The toggle's `aria-describedby` says so before activation ("Graph replaces Decompile; two panes at most"), and one polite message confirms it after. The last visible view cannot be turned off: its toggle is `aria-disabled` with the reason "At least one code view stays visible". A `views` value that names all three center views is shown by the same rule (Listing and Decompile) and rewritten to what is shown (replaceState, not at narrow widths).
- **Layout by the Code Browser's own width, not the viewport.** Two center panes sit side by side at 2 × `split-min-w` (720px) or wider and stack below that. The HexStrip spans the panes beneath them. While it is shown, the Listing's bytes column moves into it.
- **References placement.** When the evidence rail is open, References (with its Calls and Slots modes) and Outline live there, and this pane shows no second copy. With the rail collapsed, References sits beside the code at 228px when the Code Browser is at least 880px wide, and under it otherwise. It is never moved to the dock.
- **Co-visible, not tabs.** Listing and Decompile are both mounted and both visible. Hiding one is a view toggle recorded in `views`, never a tab flip, and it leaves the cursor unchanged. Turning a view on never analyzes: Decompile on a cache miss says "Not decompiled in this session · Enter to decompile"; Graph says "Not loaded · Enter to load" until Enter.
- **One cursor, reflected** (35 Reflection). Listing, Decompile, Hex and Graph share it. The focused view draws the selection shape (`selection` fill plus 3px `accent` bar). The other views draw the reflection, which keeps its existing shape: `raised` fill, a 3px `ink-muted` bar (`reflect-bar`), the words "↔ line 7" or "↔ 3 instructions", and `▸` at the exact address. In the HexStrip the statement bytes sit on `raised` and the cursor instruction carries a 2px `ink-strong` under-bar. A missing mapping is an answer ("No address mapping for line 7", "No decompiled line for 0041b213"); nothing is inferred from line order or the nearest address.
- **`r` with three or four views.** The target is fixed by the view that holds focus, never by position or by how many views are visible: Listing → Decompile, Decompile → Listing, Hex → Listing, Graph → Listing at the block's first instruction. Three views are visible at most (two center panes plus the HexStrip), and a `views` value naming all four is shown by the replacement rule, so the table covers every combination. A hidden target is shown by the same replacement rule and announced once: with Listing, Graph and Hex visible, `r` from the Listing shows Decompile in Graph's place; with Decompile, Graph and Hex visible, `r` from any of them shows the Listing in Graph's place. With no mapping, focus stays and the status line says "No mapping; focus stays".
- **Highlight all** (`h`, 35 Reflection) on a register, variable or constant marks every occurrence in each visible view of the same build, up to four sets at once, lettered A–D. Each occurrence gets a 1px `ink-strong` box (`highlight-box`) and its letter (`highlight-badge`), never an underline, because an underline means a link in code wells. The count is words on the legend chip in the well's gutter ("A eax · 7 in this function · text match"); activating the chip removes the highlight. The key is variable identity where the decompile projection gives it, otherwise exact text, and the chip says which. A fifth `h` says "Four highlights in use; remove one". Another build gets a highlight only through recorded anchors ("via anchor"); otherwise it reads "text match on build-c". Highlights are per-viewer view state, never in the URL.
- **Pointer brushing** is optional and off unless "Brush on hover" is on in View settings: a 1px dotted `brush-outline` with no bar, and the status line says "Pointer: ↔ line 7". It never moves the cursor, selection or history.
- **Following and Held.** Each center pane follows the one selection or is held. The composite header's toggle has the constant name **Hold this pane** (`aria-pressed`) and acts on the focused well, which its description names; each well's pane menu has the same item. The state words beside it read "Follows · as I move" (or "Follows · on Enter") or "Held · ResourceRef::Resolve @ build-a · 4 min". The broken-chain icon of a held pane is `ink-strong`, never a status color. Pressing it turns the focused well into a HeldPane:
  - a 2px `ink-strong` frame and the `HELD` tag, which stays visible at every scroll position because the frame alone also means other things;
  - "Held · read 13:54", what it holds (view, entity, address, basis), its own ◂ ▸ history, **Make primary**, **Follow again** and **Release**, and the read-only line;
  - a grid name that includes "held, as read 13:54".
  It never refreshes by itself. A moved basis reads "◷ Basis changed since held · Refresh", and a hold without a basis token reads "Basis at hold time not recorded". **Make primary** moves the one selection to the held location, pushes one stop and releases the hold. The pane stays open and becomes Following; a held pane never closes by itself. The other pane keeps following.
- **Update panes** is the NavigationBar's radio group (As I move / On Enter). It switches every following pane to commit-on-Enter, and each following well's header shows its mode in words ("Follows · on Enter"). It is separate from Hold this pane.
- **A following pane never decompiles on a cache miss.** It says "Not decompiled in this session · Enter to decompile" and waits for an explicit Go or Enter. Following never opens a program ("Not loaded · Enter to load") and never crosses a project.
- **Following an xref moves every view.** Enter on a callee or data token in the Decompile, on a symbol operand or flow target in the Listing, or on a References row moves the one cursor. Listing, Decompile and Hex land on the target together, one history stop is pushed and focus stays in the view where Enter was pressed. Alt+← restores every view's cursor, scroll row and caret token together, and the landing is announced once.
- **Stepping references** (`]` / `[`). The first press snapshots the References list and keeps the section as "Kept · stepping references to Archive::OpenMember · 3 of 12 · as listed 14:02" (`keep=`). It stops following while stepping; Follow selection, or Esc inside the section, ends it. The first step pushes one history stop from the origin and later steps replace it, so one Alt+← returns to the origin. Steps stop at either end and say so; they never wrap, never change build (All-builds rows are not stepped) and never touch the active worklist.
- **Contested counterparts.** In the Code Browser a contested locator opens one secondary pane that lists both evidenced addresses as candidate links, "contested · no winner". Two held panes exist only in the Compare workspace, through Compare candidates.
- **Outline popup** on `dialog-bg` with `shadow-popup`, non-modal: Blocks (entry address, name, line range), Locals (type, storage, tier; they open InlineRename and never go anywhere), Calls, Strings. The block that holds the cursor carries the selection shape and "· cursor", and moves as the cursor moves. It reads the already-loaded function; nothing is analyzed to fill it. An empty section says "none". It is the same projection as the rail's Outline section.
- **Below 700px** one view shows at a time behind an APG tablist named "Code views" (Listing · Decompile · Hex · Graph · References, 44px targets), with the line "Cursor 0041b229 · line 7 · kept when you switch views". Switching changes only which view is visible; cursor, scroll row and caret token stay. `r` ("Show reflected row" in the menu) switches the visible tab to the reflected view and keeps the reflected position. Update panes is forced to On Enter and says so. `views` is never rewritten at narrow widths. Open beside is the second segment of the split toggle (35).
- Splitters are `.ad-split-h` separators (APG Window splitter); the pane-header size menu and the View menu offer the same sizes and collapse without dragging (WCAG 2.5.7).
- **Edits confirm where they belong** (35 Confirming edits). Rename, retype and comment of a local, parameter or label open InlineRename in place, and Enter or Save posts one catalog action with no ConfirmDialog. A struct-field retype, any structure-layout change that resizes, overwrites or clears components, and a callee-signature edit go through ConfirmDialog, because they change every use of that type or callee on the build; the dialog names the type or callee, the build and the known use or caller count, or "uses not indexed". Parameter storage opens StorageEditor under the signature line. Browsing, following, the Outline, Hex and References read cached or already-loaded evidence and never start analysis, import, compile or any mutation.
- Both surfaces implement it over the same location, cursor and reads; there is no new backend or state owner. The static 8080 surface may stack the views as panels with the same cursor and reflection, and opens Open beside as a new window ("Open beside (new window)"); no field exists on only one surface.

**Analysis-tab flips it removes.** Disassembly ⇄ Decompiler ⇄ Hex ⇄ Graph flips go: the views are co-visible toggles (`views=listing,decompile,hex,graph`), never exclusive tabs. The Xrefs tab becomes References beside or under the code, or the evidence rail's References section. Strings used by the current function move into the Outline. Program-wide Strings, Imports, Exports, Sections, Symbols and Bookmarks are navigator scopes (Workstation layout); program Info is the build crumb's Peek and the rail's build header. Moving focus between views uses Tab or the `g` leader, not a tab switch.

**Linking**

- **Publishes:** `addr` (the cursor) with replaceState after the settle for moves inside one function; Go pushes one stop with `build` and `addr`. `views` changes and `hold=kind:id@build[:addr][~basis]` (at most two) use replaceState; Make primary pushes one stop. Stepping references publishes `keep=` for the kept section.
- **Follows:** the primary location after the 200ms settle. Listing, Decompile and Hex are cached panes and follow as you move; Graph commits on Enter. Under Update panes: On Enter, every following well commits on Enter. Each center pane is holdable with Hold this pane.
- **Targets rendered:** every link of Listing, DecompileView, HexStrip, GraphPane and References (addresses and symbols → the Code Browser at that build and address; types → `type=`; jobs → the dock Jobs record), and the Outline's block, call and string links. The link menu is the one flat menu of 35: Open · Open beside · Peek; Edit (code tokens only, from `GET /api/v1/actions`); Reveal in; Copy.
- **Peek source:** the peek cache: cached listing rows, cached decompile lines and stored facts of the target. Nothing is decompiled or fetched for a Peek.
- **Absent copy:** "Not loaded · Enter to load" (Enter or one Load button); "Not decompiled in this session · Enter to decompile"; "No address mapping for line 7"; "No decompiled line for 0041b213"; "unresolved import" for a callee with no symbol; "contested · no winner" with both candidate links.
- **Target-size exception:** token links in code wells use the inline exception (underlined on the current, hovered or focused line only); toolbar controls are 24px, 44px below 700px, and with a coarse pointer each row has one 44px row-menu button carrying the link menu.

**Keyboard**

- Each view is one tab stop: Tab goes Listing → splitter → Decompile (or Graph) → Hex → References toolbar → References grid. F6 and Shift+F6 still cycle the workstation regions.
- Enter goes, Shift+Enter opens beside (a Held pane), Alt+↓ peeks and Shift+F10 opens the link menu, in every view (see DecompileView and XrefPanel). Token links in the wells use the documented underline exception.
- Alt+← and Alt+→ move every view back and forward together. They act on the primary history only.
- Code-scope keys from `keymap.json`, only while focus is in a code well and remappable (WCAG 2.1.4): `r` moves focus to the reflected row (table above), `h` highlights all occurrences, `x` focuses References, `]` and `[` step through references.
- The `g` leader shows which-key hints: `g l` Listing, `g d` Decompile, `g h` Hex, `g r` Graph, `g x` References, `g o` Outline (`code.outline`), `g 1…7` layout presets. Below 700px `g l`, `g d`, `g h` and `g r` also switch the visible view.
- The Outline (`g o`, the toolbar's Outline button or the palette's "Outline of this function"): ↑/↓ move, Enter goes, F2 on a local renames it, Esc closes and returns focus.
- The view toggles and Hold this pane are buttons: Space or Enter toggles.
- Below 700px the Code views tablist follows APG Tabs: ←/→ and Home/End move, the cursor stays.
- Esc follows the one order in `keymap.json` `escapeOrder`; in a held pane it returns focus to the primary pane and never releases the hold.

**Accessibility**

- The composite is a `section` named "Code Browser"; each view is a labelled region with an h3 holding a named grid ("Listing, ResourceRef::Resolve, build-a", "Decompiled C, ResourceRef::Resolve, build-a", "Bytes, build-a .text, …"). A held grid's name says "held, as read 13:54".
- The Views bar is an APG Toolbar with one tab stop; the replacement and last-view rules are in each toggle's `aria-describedby`. Hold this pane is `aria-pressed` with a stable name, visible state words beside it and an `aria-describedby` sentence naming the focused well. Held is a word and a frame, never color alone.
- After Go or Back the new place is announced once in the polite region ("Back to ResourceRef::Resolve, line 7"). Cursor moves and brushing announce nothing; `r` announces once ("Decompiled C, line 7, from 3 instructions, 0041b213 to 0041b21b" or "No mapping; focus stays"); a view replacement is announced once (WCAG 4.1.3).
- Distinct cues: focus is an outline; the cursor is `selection` plus a 3px `accent` bar; reflection is `raised` plus a 3px `ink-muted` bar and words; brushing is a dotted outline without a bar; a highlight is a 1px `ink-strong` box plus its letter, with the count in words on its legend chip. In forced colors the reflection is a dashed CanvasText outline, the highlight a CanvasText box with its letter, and brushing is off.
- Screen-reader verbosity is the one per-viewer View settings value; the wells read their rows under it. Accessible View (Alt+F2, the palette, the Help menu or the pane-header button) opens the exact text of the focused well; GNOME and KDE take Alt+F1 and Alt+F2, so those paths always exist.
- WCAG 3.2.1 and 3.2.2: toggling a view, Hold this pane or the single-view tab never moves the cursor or switches the build.
- WCAG 1.4.10: below 700px one view at a time; only code rows scroll horizontally, each inside its own well. WCAG 2.4.11: `sticky-offset` includes the composite header and every well sets `scroll-padding`.
- The Outline is a non-modal `role="dialog"` named "Outline · ‹function›" with grouped lists; `aria-current` marks the cursor's block. It opens on request only, never on focus.

**Removes switching** (counts from the plan ledger, which is authoritative):

- J10 relate an instruction row to its decompiled statement: 6 → 0 at ≥700px (2 below 700px), credited to this unit (U173).
- J09 follow a cross-reference and return: 4 → 0 view switches, credited to References in place (U177). Counted as 1 region move for the first reference, 0 for each further one, and 1 Alt+← back; below 700px, 2 per reference by tab, or 0 with `]`/`[`.
- J16 explore the call graph beside code: 3 → 0 when Graph and Decompile are the two panes (2 per node below 700px).
- J36 and J37 are credited elsewhere (typed links; NarrowFlow, 6 → 2); this composite keeps the cursor across every narrow view switch.
