# GraphPane

The function graph beside the code: basic blocks of the current function, or the calls around a function, drawn as focusable links whose arrow keys follow edges, with zoom and pan buttons, bounded depth that says "truncated" in words, a list form (APG tree) that is always one toggle away, and a rooted Calls graph that works as a navigator: Enter on a node moves the selection while the graph keeps its exploration.

**Use it** as the Graph view of the Code Browser, beside Listing and Decompile (`views=…,graph`), never as a separate page. **Blocks** shows the control-flow graph of the function holding the cursor. **Calls** shows callers or callees around one root function to a bounded depth; walk it with the arrow keys and press Enter on each node to read that function's code in the primary views. **Hold this pane** when the graph should stop following altogether.

**Consumer provides** for Blocks: the function, build and the blocks from existing analysis (start address, instruction count, role entry or exit, up to two key lines such as calls and the terminator) and typed edges (taken, fall-through, unconditional, back edge); which block holds the cursor; and whether the function exceeds the drawing bound. For Calls: the root, direction and depth, and nodes and edges from the stored call index with each node's callee count and whether it was cut by the depth or breadth bound. In both: layout positions, the analysis generation and read time, and the not-loaded state for builds that are not open.

- Pane: `pane` card with the standard header (kicker "Graph", the mode and function, the build and counts, sync state ("Following · sync A"), **Graph | List** toggle, **Hold this pane**) and an APG Toolbar: **Blocks | Calls**, **Depth 1 | 2 | 3** for Calls, **Zoom out · 100% · Zoom in · Fit**, **Pan ← ↑ ↓ →**, **Center on cursor**. Nothing requires dragging (WCAG 2.5.7); the canvas also scrolls in both directions in its own `well` viewport.
- Nodes are real `<a href>` links over the location schema, absolutely placed on a canvas: `pane` fill, 1px `line-control` frame, `type-code-small` mono. The address is the link text (`address`, dotted underline); mnemonics `ink-strong`, symbol operands `lane-identity-ink`, counts and roles ("entry", "exit", "root") in `ink-muted`. A Calls node shows the function name in bold `ink-strong` over its address.
- Edges are drawn in an `aria-hidden` SVG under the nodes, 1.5px `ink-muted` with explicit triangular heads: solid for taken and unconditional, dashed for fall-through, dotted for back edges (loops). Conditional and loop edges carry the words "taken" and "loop" on the drawing, and every edge is written in its nodes' accessible names. A legend under the canvas names each stroke. Never color alone.
- The block holding the cursor (in a Calls graph, the node holding the primary selection; in a held graph, the pane's own cursor) uses the selection shape: `selection` fill, 3px `accent` bar and the word "cursor" or "selection" in the node. Focus is a separate 2px `focus` outline; hover is `row-hover-bg`.
- **Bounded, and says so.** Calls draws at most the chosen depth (1–3, default 2) and three children per node. Nodes at the depth limit say "depth limit · N" in italic `ink-muted`; cut children become a dashed "+N more · not drawn" button; the footer sums it: "Truncated: depth limit reached on 3 functions; 4 callees of the root not drawn". Blocks draws at most a bounded number of blocks nearest the cursor for very large functions and says "Truncated · 412 blocks; drawing the 40 nearest the cursor". The list form always has everything the index holds.
- **List form** (Graph | List): the same nodes as an APG tree of links in the Navigation Treeview pattern (`a role="treeitem"` with `aria-owns` groups), one row per node under its parent, with its address, counts and the same words ("depth limit reached · 3 callees", "no callees in the index", "selection here" or, when held, "this pane’s cursor"). A node reached twice is listed under each parent; a recursion is "↺ recursive, listed above" and not expanded. Tree items follow the composite-widget rule: no underline, 28px rows, 3px inset focus.
- **Following** (default, "Following · sync A"): an expensive pane, so across functions it commits on Enter. When the selection moves elsewhere, the old graph stays with dashed node frames and a StateNotice "◷ Showing ResourceRef::Resolve · The selection moved to FUN_0041c880" with **Draw now**; late responses for a superseded selection are dropped. Inside the same function the cursor block updates at once; no fetch is needed.
- **The navigator is the following Calls graph with its root kept.** Enter on a node is an ordinary Go: the primary selection moves there with one history stop and the code views follow. While the new selection is a node already drawn, the graph keeps its root, depth, open nodes, zoom, scroll and focused node and only moves the selection shape; it never re-centers. When the selection leaves the drawn graph, it commits on Enter like any expensive pane. **Re-root on selection** makes the selected function the new root.
- **Held** follows the linked-views contract exactly. The constant-named toggle **Hold this pane** (`aria-pressed`) freezes the graph to its root × build with a basis token; the state words become a Held chip, "Held · Actor::LoadFromTemplate @ build-a · 6 min", in a 2px `ink-strong` frame, with "Held · read 13:52 · basis … · unchanged" (or "◷ Basis changed since held · Refresh"; "Basis at hold time not recorded"). Inside a held graph, Enter moves that pane's own cursor and its own Back/Forward, never the primary location. **Make primary** (Enter on the Held chip, or the button) is the only way it moves the one selection, to the pane's cursor. It never refreshes by itself and never switches its build.
- Read-only by construction: blocks come from existing analysis and calls from the stored call index. Drawing, zooming, holding and expanding "+N more" never start analysis, decompile, open a program or run reference analysis. A build that is not open says "○ Not loaded. Open to read it."
- Motion: none. Zoom and pan are instant; the 120ms landing flash of the code views is theirs, not the graph's. Under reduced motion nothing changes.
- Both surfaces draw from the same nodes, edges and layout; the static 8080 surface may render only the list form plus a static SVG, never dropping the words.

**Linking**

- **Publishes:** following: the primary location (`entity`, `build`, `addr`) on Enter, one history stop (focus lands on the Listing row); `views` when the pane is shown or hidden (replaceState). Held: `hold=graph:…@build[~basis]` (replaceState); Make primary pushes one stop.
- **Follows:** commit-on-Enter (an expensive pane); inside the same function the cursor block follows at once. Holdable with **Hold this pane**.
- **Targets rendered:** block and function nodes → the Code Browser at that build and address (focus lands on the Listing row; in a held graph, the pane's own cursor) · the selection link in the header · the held basis → the ProvenanceStamp detail. Link names start with the visible address or function: "0041b240, 3 instructions, ends jne 0041b216 …".
- **Peek source:** Alt+↓ on a node reads the peek cache: a block's cached instructions, a function's facts and counterparts; Shift+K inside the Peek keeps it. Nothing is fetched and nothing is decompiled.
- **Absent copy:** "no callees in the index" · "not indexed here" (beyond the stored call index) · "depth limit · N" and "+N more · not drawn" · "Truncated · 412 blocks" · "Not loaded. Open to read it." (a build that is not open).
- **Target-size exception:** none; nodes are at least 40px tall and 120px wide, toolbar buttons 24px, tree rows 28px; 44px below 700px.

**Keyboard**

- The canvas is one tab stop with roving focus; Tab lands on the cursor or selection node.
- ↓ follows an outgoing edge to a successor (callee); ↑ follows an incoming edge back to a predecessor (caller), preferring the edge you arrived by. When a node has several, ←/→ move among the alternatives of that edge set and the move is announced ("successor 2 of 2, taken"). Home goes to the entry block or root, End to the exit block or last node.
- Enter goes: in a following graph the primary selection moves and focus lands on the Listing row, as for any address link; the graph keeps its own focused node, so returning to the graph resumes the walk at the same node. In a held graph Enter moves the pane's own cursor and focus stays in the pane. Shift+Enter opens beside. Alt+↓ peeks. Shift+F10 opens the link menu (Open, Open beside, Peek; Reveal in Code Browser, Compare, Navigator; Copy link, Copy address).
- `+`, `-` and `0` zoom in, zoom out and fit while focus is inside the canvas only; they are remappable and can be turned off (WCAG 2.1.4). The viewport scrolls to keep the focused node visible (operator-initiated); it never pans on its own.
- In the list form: APG Tree keys (↑/↓, → opens or moves to the first child, ← closes or moves to the parent, Home/End, typeahead on names); Enter goes; Enter on "+N more" lists them from the index.
- Ctrl/Cmd+Enter on a node keeps the browser's new tab.

**Accessibility**

- The canvas is `role="group"` named "Control-flow graph of ResourceRef::Resolve, build-a, 5 blocks, 7 edges" and described by the legend. Each node's name starts with its visible address or function and adds its role, size, terminator and edges in words: "0041b240, 3 instructions, ends jne 0041b216. Successors: 0041b216 taken, loop back edge; 0041b246 fall-through." The SVG is `aria-hidden`.
- The list form is the structural equivalent and is always available by toggle; a screen-reader user can stay in it. Toggling keeps the focused node.
- `aria-current="true"` marks the cursor block, the selection node, or a held pane's own cursor, with the word visible too ("cursor", "selection", "this pane's cursor"). A Go from the graph announces once: "Selection: Archive::OpenMember, build-a. The graph keeps its root." Moving focus announces nothing beyond the node name (WCAG 3.2.1).
- Truncation is text in the node, the footer and the tree, never only a dashed frame. Node text truncated by the node width is complete in the accessible name, the list form and the Peek.
- Targets: nodes are at least 40×120px; toolbar buttons 24px; 44px below 700px, where the pane opens in the list form by default.
- Forced colors: frames, edges, heads and labels map to `CanvasText`; the cursor node maps to `Highlight`/`HighlightText`.

**Removes switching:** J16, explore the call graph and read code of nodes along the way, goes from 3 switches per node (graph tab, code tab, back) to 0: the graph sits beside the code and keeps its root while each Enter shows the node's code in the primary views. J15, diagnosing a decompile artifact, loses its graph-tab round trips (part of 6 → 2 with the Code Browser composite).
