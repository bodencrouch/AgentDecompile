# ProblemsList

The dock's Problems tab: one row per unmet predicate, failure or external action, grouped by objective. Each row is a set of typed links to the entity, the evidence and the job, carries a StageChip, and expands its FailureRecord in place.

**Use it** as the Problems tab of the activity dock on both surfaces (`dock=problems`, `g p`), and anywhere an objective needs "what is blocked and why" without leaving the current view. It is the list form of ObjectiveSummary's unmet predicates; it never replaces FailureRecord, it hosts it. It is an existing component amended in place.

**Consumer provides** the objectives from the shared projection (name, next automatic action with its wake condition, independent work that continues); per problem: kind (unmet predicate, failure, external action), the stable reason phrase, the governing fact and its state for a predicate, the FailureRecord fields for a failure, the entity or scope with its build, the evidence reference (receipt, diagnostic, basis digest or pipeline node), the job when one exists with its catalog verb for the StageChip, the observation time it started waiting and any deadline; for an external action its deduplication key, report count and the objectives it blocks; and the snapshot time and projection revision.

- Three kinds, each glyph plus word: **Failure** (✕ `fact-failed`, with its classification chip: mismatch, transient, resource, policy), **Predicate** (the governing fact's own glyph: ○ not_run, ◷ stale, ✕ failed, ? unknown) and **External action** (⚑ `fact-stale`, the approval-required glyph). The kind word is `type-kicker` in `ink-strong`; the reason is the stable phrase from the FailureRecord ("Provider paused for this input revision"), never a log line.
- **Grouped by objective**, as an APG Treegrid. A level-1 row names the objective, its problem count, the next automatic action as a sentence with its wake condition ("verify recipients when a3f9 finishes"), and how much independent work continues. If there is no automatic action it says so and names what is needed. Group rows sit on `pane`; problem rows on `chassis`. There is no second grouping mode.
- **StageChip per row.** A row whose job's verb is mapped in `catalog_verbs` shows its StageChip; otherwise "stage: unmapped".
- **Node filter.** Enter on a PipelineMap node (for example gate-4) applies `f=node:gate-4`, shown as the FilterChip "Under gate-4 ×" above the grid. It filters; it never regroups.
- **External actions are deduplicated.** One external action appears once, in its own first group, with "N reports, shown once · blocks K objectives". Each objective it blocks shows a one-line "Also blocked by" row that links to it and says "(not repeated)". It reappears only on material change. Dismissing is not resolution; there is no dismiss control.
- **Disclosure, not a page.** A failure row expands in place (→ or a click on the twisty) into a level-3 row holding the full FailureRecord in its fixed field order: reason, lifecycle rail, classification, scope, evidence, owner and resource, freshness, attempts and budget, recovery action, wake condition, what continues, and escalation only when unavoidable. The recovery action is never folded into the attempts and budget. The evidence excerpt is read on expand only. Collapsing returns focus to the row.
- **Waiting column = starvation per row.** Each row shows how long it has waited (`type-code-small` mono) and sorts oldest first within its group (`aria-sort="descending"`). The oldest row in the list says "oldest". A job past its deadline shows ✕ `fact-failed` and "+18m past deadline" in words and names its failover; "deadline ≠ termination". Ages are observed durations from the snapshot, never ETAs or percentages.
- **Selection only** is the dock-level toggle (Workstation). This tab's checkbox reflects it: rows are limited to the one primary selection, the logical entity across builds or the concrete build when the selection is build-scoped. The FilterChip "Selection only: ‹entity› · ‹build› ×" shows while it is on, and rows drop the entity column value that is now implied. With nothing matching it shows a StateNotice: "No problems for ‹entity› on ‹build›. N problems elsewhere" with **Show all**, one activation.
- **Kind chips** (`ad-filt`, counts in mono) filter by kind; unchecked chips are dashed.
- **Worklists come only from Collect.** **Collect into worklist…** (`w`) hands the current rows, in order, to the MarksList dialog. **Step problems** does the same in one activation and makes the snapshot the active worklist ("Problems · 2 of 5 · snapshot 14:02"). F8 steps only the active worklist; with none, it says "No active worklist" and names these two paths.
- **Freeze updates** (`aria-pressed`) holds this region: "Frozen at 14:02 · 7 events since", queuing without dropping and resuming on request (WCAG 2.2.2). Actions from frozen rows act on the current record.
- **Refreshes never move the reader.** A new projection keeps focus, scroll, expanded rows and the selected row. A problem that resolves while focused stays in place struck through with "resolved 13:59" until focus leaves it; nothing jumps under the cursor.
- Disconnected or reconnecting: the last snapshot stays, read-only, visibly dated ("Showing problems from 13:58"), and ages say they count from that snapshot. Nothing is hidden or reset.
- Rows are 28px minimum, twisties 24px, `line` separators, the selected row `row-selected-bg` plus the 3px `accent` bar with state words promoted to `ink-strong` (glyphs keep their color). Below a 620px container the row reflows to reason on top, links and age beneath.
- **Coarse pointer.** Each row has one 44px row-menu button carrying the one link menu; there is no long-press. Below 700px rows and twisties are `touch-h`.
- Both surfaces render the same projection that drives the CLI and agents; the footer names the snapshot time and projection revision. The static 8080 surface may render the same rows as a plain treegrid or `<details>` in the same order; it never drops the grouping, the ages or the in-place record.

**Linking**

- **Publishes:** nothing by focus. Enter on a link goes (one history stop). `dock=problems` and `f` carry the tab and its filters: a filter applied from a link pushes, and typing a filter or removing a chip replaces. A copied link reopens the same filtered list.
- **Follows:** the primary selection only while Selection only is on (after the settle); otherwise the whole project, following nothing. Not holdable.
- **Targets rendered:** entity and counterpart → the Code Browser at that build · receipt → the receipt card · compiler diagnostic file(line) → the SourceRepairDiff line (`f=src.line:resource.c:41`) · basis digest → the ProvenanceStamp detail · job → the dock Jobs record · pipeline node and StageChip → the PipelineMap node · "N recipients" → the entity list filtered in place.
- **Peek source:** Alt+↓ on a link reads its cached Peek: the stored receipt, the stored job record as of the dock's last read, the node's model text, cached listing lines. The FailureRecord evidence excerpt is read only on expand, never on focus, hover or prefetch.
- **Absent copy:** "no job admitted", "external · no job", "whole build" and "stage: unmapped" are words, never links. A counterpart that is not resolved says "unresolved on build-d".
- **Target-size exception:** inline links in the evidence cell rely on the WCAG 2.5.8 inline exception inside a 28px row; twisties and checkboxes are 24px; 44px below 700px and with a coarse pointer.

**Keyboard**

- APG Treegrid with one tab stop. ↑/↓ move between rows, Home/End to the first and last row, Ctrl+Home/End likewise across groups. → expands a collapsed row, or on an expanded row moves into its first cell; ← collapses, or moves to the parent row, including from inside an expanded FailureRecord.
- Within a row, ←/→ move between cells; Enter on a link cell goes; Shift+Enter opens it beside; Alt+↓ peeks it; Shift+F10 opens the one link menu. On the reason cell, Enter toggles the FailureRecord.
- In an expanded FailureRecord, Tab moves through its links. Esc follows the one Esc order in the Keymap section.
- Space or x (`list.check`) checks the focused row; checked rows show a 24px checkbox cell and a count chip, never a second fill. `w` collects the checked rows, or every visible row when none is checked, in their current order. The toolbar comes before the grid in Tab order.
- This grid binds single-letter commands (`list.move` j/k, `list.worklist` w, `list.mark` m then a letter, `leader` g), so typeahead starts with `/` into a visible filter field. Keys come from `keymap.json`, act only while focus is in the grid, and can be turned off or remapped in KeymapSettings (WCAG 2.1.4).

**Accessibility**

- `role="treegrid"` named "Problems by objective, oldest first", with `aria-rowcount`; rows carry `aria-level`, `aria-posinset`, `aria-setsize` and `aria-expanded` where they expand; the expanded record is a level-3 row whose single cell spans the columns and holds a named group.
- A row reads as a sentence: "Failure, mismatch: Provider paused for this input revision. ResourceRef::Resolve on build-c. Evidence resource.c line 41. Job 0b17, waiting. Stage 4. Waiting 22 minutes." Glyphs are `aria-hidden`; every link's name carries type, target and state.
- The polite region announces once per filter change or problem transition ("5 problems in 3 groups. Oldest: ABI checks not run on build-d, 3 hours 40 minutes"), never per poll. An external action that newly blocks the action in hand is the only assertive message.
- Expanding or filtering changes only this list (WCAG 3.2.2); focus never moves on its own (3.2.1), except to the nearest row, announced, when the focused row is removed. `scroll-padding-block` keeps the focused row clear of the sticky header (2.4.11).
- Every state is a glyph and a word; the waiting age is text, not a bar.

**Removes switching:** J04 ("why is this blocked and what continues") goes from 5 switches to 1: the record, diagnostic and job are in the row or its Peek, credited to U182. It supports J28 (the oldest wait, credited to U181), J35 (the stale Peek, credited to U174) and J02 (credited to U180); add 1 below 700px wherever the dock is involved.
