# SplitCompare

Two or three panes side by side for the same logical entity on different builds, or for target and rebuilt output, aligned on matched anchors, with scroll lock, difference stepping (F7 / Shift+F7), collapsed unchanged regions and an accessible text diff.

**Use it** wherever Open beside lands (Shift+Enter or Shift+click on a counterpart, address or symbol): from a CounterpartStrip item, a CounterpartMatrix row, a Peek, an XrefPanel row or a ReviewDetail. It is the one secondary-pane form of the workstation. It replaces "switch the inspected build, read, press Back".

**Consumer provides** the primary location (project, logical entity, inspected build, address) and the split build or builds (`sp`). Per pane: the concrete build and address, or the absence with its locator status and ladder outcome; rows already cached from existing analysis or the stored listing, decompile or bytes; and its ProvenanceStamp (reused, fresh or historical, generation, read time). Per pair: the divergence class, relation kind and components, the IdentityEdge state with its channels and margin, the anchor row pairs with their evidence channel, and the difference hunks. For target vs rebuilt: the object pair, the variant (C+floor or max-C), the Local match fact and the comparison receipt.

- **One selection owner.** The first pane is the primary pane and says "Follows selection" with the chain icon. Every other pane is **derived** ("Counterpart of #88 · derived", recomputed from the selection's logical entity on its own fixed build, with a **Hold** button) or **Held** (HeldPane: "Held · build-c · 4 min ago" in a 2px `ink-strong` frame, with Make primary, Follow again and Release). A derived pane never changes its build. A held pane never changes at all until Refresh, Follow again or Release.
- **Opening a split never changes the primary selection or its inspected build.** The footer says so. Close split returns to one pane and puts focus in the primary pane. Only Go (Enter on an address or symbol) moves the selection, and a build switch is stated before activation and announced after it ("Inspected build: build-c").
- **Never implies equivalence.** The header always shows the divergence class as framed notation plus words: `1↔1` structural match, `1↔N` split-or-inlined candidate, `≠` diverged (dashed frame). Beside it: the relation kind, the component count and the IdentityEdge state as line style plus word, with its channels and margin. The header states "aligned ≠ equivalent". Rows align only on evidenced anchors; between anchors rows are paired by order and the pairing claims nothing. A held pane on another entity is not aligned, and the header says "no correspondence is drawn".
- **An absent counterpart is a pane, not a blank.** It keeps the build header with the word "absent" and its LocatorGlyph (◌ unresolved, ⋯ ambiguous, ⇉ contested) in a dashed `line-control` frame on `chassis`. The body gives the reason: "diverged — counterpart structurally different, possibly inlined/split", the ladder outcome with members tried, and a typed link to the ladder evidence. Nothing is aligned or inferred. Ambiguous and contested panes list every candidate address as a link and pick none.
- **Read-only by construction.** Panes read cached listings, stored listings and receipts. A pane whose program is not open says "○ Not loaded. Open to read it." and names why; opening that program is an explicit action inside the pane. A split never analyzes, imports, compiles, matches or admits work.
- **Rows.** Each pane is a `code-bg` well with `shadow-inset` and `type-code` on fixed 18px lines, so rows stay level across panes. Addresses use `address`, mnemonics `ink-strong`, symbols `lane-identity-ink`. The marker column pairs a glyph with a word (spoken, and in the legend): `↔` anchor (`lane-identity-ink`; the matched token gets a solid 2px `lane-identity-ink` underline), `±` differs (`fact-stale`; the differing token gets a wavy `fact-stale` underline), `−` only on the left build and `+` only on the right build (`ink-strong`), and a hatched `line` filler for "no line on this side". Differing and one-sided rows sit on `raised`. There is no red or green, because neither build is right or wrong.
- **Current difference.** The current hunk has a 2px `ink-strong` outline in every pane, and the toolbar says "difference 2 of 5". The caret line in the focused pane takes the selection shape (`selection` plus a 3px `accent` bar). The aligned line in the other panes takes a 3px `line-control` bar ("aligned with the caret line").
- **Collapsed unchanged regions** are one 26px row per pane, "▸ 9 unchanged lines · 0041b220–0041b23e · Expand", in a dashed `line-control` box on `pane`. Expanding one region expands its partners in every pane. Collapse unchanged is a toggle with `aria-pressed`.
- **Split components** (1↔N) are separated by a labelled rule row in every pane ("component 2 of 2, split part · 00083120"), so the second component is never folded silently into the first.
- **Scroll lock** ("Scroll lock · on anchors", `aria-pressed`) scrolls every pane together and keeps anchor rows level. When it is off, each pane scrolls on its own and anchors stay marked. It is disabled when nothing is aligned, for example a held pane on another entity or an absent counterpart.
- **Text diff** (`aria-pressed`) replaces the panes with one ordered list. Each item begins with its word (anchor, same, differs, only on build-a, only on build-c, unchanged) and gives both lines with their build names. It wraps instead of scrolling.
- **Views.** Listing, Decompile and Bytes share one alignment and one difference count. A view that is not already cached shows Not loaded; it is never computed on open.
- **Target vs rebuilt** uses the same frame with "target" and "rebuilt" in place of build names, plus the object pair, the variant, Local match as a FactBadge and the comparison receipt with its ProvenanceStamp (fresh or historical). The header says "local zero ≠ full-image or behavior proof". Relocation-aware equality is written on the row where it applies.
- **Stale responses never land.** Each pane's read carries the selection generation. After a 200ms settle, a derived pane keeps its previous rows dimmed with "Loading counterpart of ‹name›" and drops late responses for superseded selections.
- **Layout.** At most three panes. The component is the workspace's one secondary center pane; its third column exists only in the Compare workspace. Pane headers align across panes (CSS subgrid). Below 900px of component width a third pane wraps to a second row. Below 640px, and below `bp-single-pane`, one pane shows at a time behind a tablist ("build-a · follows | build-c · derived"). F7 still steps, and it switches the shown pane when a difference exists only on the other side.
- **Both surfaces.** The static 8080 surface draws the same header, markers, legend and text diff, and may place the split as a second page region. The full workspace adds subgrid alignment and scroll lock. Both use the same reads and the same URL.

**Linking**

- Publishes `ws=compare`, `sp` (the split build; repeated for a third pane), `hold` for held panes (`kind:id@build`) and `v` for the view, for example `?project=corpus-alpha&entity=88&build=build-a&addr=0041b240&ws=compare&cmp=build-c`. Opening a split is a pushState stop; stepping differences uses replaceState.
- Follows the primary location (`p`, `e`, `b`, `a`). Derived panes resolve `e` on their split build. Held panes ignore location changes.
- Renders addresses and symbols in every pane (Code Browser for that build), the logical id (Compare with the CounterpartMatrix), the identity edge (IdentityEdge evidence), receipt and basis ids (receipt card, ProvenanceStamp detail) and the ladder (EvidenceRail for that entity and build).
- An absent target is an absent pane with the word "absent", its locator word, the reason and a link to the ladder evidence. It is never a link to a guessed address.

**Keyboard**

- **F7 / Shift+F7**: next and previous difference across all panes. Focus moves to the first line of that difference in the focused pane, and "Difference N of M" is announced once. The keys work while focus is anywhere in the split (toolbar or panes). The surface suppresses the browser's caret-browsing default for F7 only there. The keys can be remapped, and the toolbar buttons and the palette command "Next difference" are the other paths.
- **Tab order**: header links, then the toolbar (one tab stop; ←/→ between controls; APG Toolbar), then each pane's grid from left to right (one tab stop each). F6 treats the whole split as part of the center region.
- **In a pane grid**: ↑/↓ move by line, PageUp/PageDown by screen, Home/End to the row start and end, Ctrl+Home/Ctrl+End to the first and last line. With scroll lock on, the aligned line in the other panes follows. Enter or Space on a collapsed region expands it in every pane.
- **Links in a pane** use the shared grammar. Enter goes (moves the one selection; a build switch is announced). Shift+Enter opens that target beside and replaces the derived pane, never a held one. Alt+↓ peeks. Ctrl/Cmd+Enter opens a browser tab. Shift+F10 opens Reveal in (Code Browser · Compare · Evidence · Navigator · Dock) with Hold pane and Copy link.
- **Ctrl/Cmd+\\** (`split.open`) opens a split for the current selection, beside it on the next build that has a counterpart. **Ctrl/Cmd+Shift+\\** (`split.swap`) swaps pane positions; the primary pane still follows. **Ctrl/Cmd+Alt+2** is the Compare layout preset.
- **Alt+PageDown / Alt+PageUp** (`build.next`, `build.prev`): with focus in a derived pane, they move that pane to the next or previous build that has a counterpart, skipping absent builds. In the primary pane they switch the inspected build, and the switch is announced.
- **Alt+F2** (Accessible View) opens the text diff of the current split.
- Esc moves focus from a secondary pane back to the primary pane. Close split is a button, never Esc, so Esc cannot discard a comparison or release a held pane.

**Accessibility**

- The split is a `section` named by its title. Each pane is a `section` named by its build. Each pane's rows form a `role="grid"` named like "Listing, build-c, counterpart of ResourceRef::Resolve, aligned with build-a", with `aria-rowcount`.
- Marker glyphs are `aria-hidden`. Every row begins with an `sr-only` word (same, differs, "anchor, rare ref", only on build-a, no line on build-c), and differing tokens are prefixed "differs:".
- The current difference is a `rowgroup` labelled "Difference 2 of 5, current", and the caret line has `aria-current="true"`. Each step is announced once in the polite region ("Difference 2 of 5: 0041b240 jz differs; 0041b242 only on build-a"). Nothing is announced on scroll.
- Divergence notation is framed text with its words beside it. The identity edge is a line style plus a word. Color is never the only carrier.
- Toggles use `aria-pressed`. Collapsed regions are buttons with `aria-expanded`. The narrow pane switcher is an APG tablist.
- Text diff is the primary accessible form: one ordered list with explicit words that reflows to 320px without horizontal scrolling (WCAG 1.4.10). Code panes scroll sideways only inside their own well.
- WCAG 3.2.1 and 3.2.2: focus, arrows and difference stepping never switch the build or move the selection. Hold, Release, Follow again and Make primary act only when activated. WCAG 2.4.11: `scroll-padding-block` keeps the current difference clear of the sticky pane header. WCAG 2.5.8: toolbar and header controls are 24px, and 44px below 700px. WCAG 2.5.7: nothing needs dragging, because pane widths are set by the splitter keys and the View menu.

**Removes switching:**

- Compare a function with its counterpart on another build: Code Browser → Compare workspace → CounterpartMatrix row → counterpart replaces the inspected build → Back → Back. Before: 4 view switches, and the inspected build changes twice. After: Shift+Enter on the CounterpartStrip item, 0 view switches, inspected build unchanged.
- Read why a Local match failed: Code Browser → Recovery → Evidence (ObjectDiff receipt) → back to the listing. Before: 3 switches. After: 0, with target vs rebuilt beside the listing.
- Step through the differences between two builds. Before: two windows scrolled by hand, re-finding the aligned line after every scroll. After: F7, 0 switches.
- Keep one build's function in view while browsing another entity. Before: a second browser window that drifts out of date, or a Back and Forward round trip (2 switches) for every look. After: Hold, 0 switches.
